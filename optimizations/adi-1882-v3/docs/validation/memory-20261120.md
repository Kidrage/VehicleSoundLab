# 1882 V3 固定 V10 内存优化：2026-11-20

本次目标按用户确认口径：算法 RAM＋栈小于 600 KB，代码和芯片缓存另列。结果是固定 V10 的 PC FP32 链接验证；尚未取得 CCES 工程、目标 map 或板端栈高水位，不能据此宣布 ADI 实测达标。桌面给定目录只有交付源码、App 和报告，未找到可直接构建的 CCES 项目。

## 结果与统计边界

按更严格的 600,000 字节验收，而非 600 KiB。最终 DLL SHA256：
`78e3f84004a30be857de8107b5745e5972a5eaf97200ee72900783dfb5f258fc`。

| 项目 | 字节 | KiB |
|---|---:|---:|
| 全部可写静态 RAM | 335,376 | 327.52 |
| 栈预留，未冒充高水位 | 65,536 | 64.00 |
| 调用方 256 帧立体声 float 输出 | 2,048 | 2.00 |
| 上述三项 | 402,960 | 393.52 |
| 全部只读非代码节，保守按 RAM 计算 | 194,354 | 189.80 |
| **保守合计** | **597,314** | **583.31** |
| 严格 600,000 B 余量 | 2,686 | 2.62 |
| 代码，另列 | 165,816 | 161.93 |

只读计数连 Windows PE 的异常表、重定位和资源元数据也包括在内，避免把可能驻留 RAM 的参数漏算。目标 ABI、链接对齐和库实现不同，最终数值仍由目标 map 决定，当前严格预算余量较小。272 KiB 芯片缓存按用户口径另列，不计入算法 RAM；整机 RTOS、音频 DMA 和驱动的额外缓存也不在这份算法预算里。

本预算对应单实例、量产干声立体声输出，`vsl_source_process(h, stereo, NULL, 256)`。23 声道导出能力仍保留，但若调用方另外常驻 256 帧完整 packed 缓冲，必须额外计入 23,552 B，不能继续称为低于 600,000 B。若需要现场模块诊断，宜边采集边输出或复用外部测试内存；诊断版的资源另测。对外支持的最大块仍为 1024；如常驻 1024 帧立体声输出，需比本表额外增加 6,144 B。

PC 同口径可写静态节由 12,776,320 B 降至 335,376 B，减少 97.38%。这只比较已链接的静态占用，旧桥接加载阶段可能存在的堆分配未算入旧数；不能将它直接当成截图 DDR 或整机 RAM 的下降率。

## 原来为什么这么大

截图是链接预留与段分布，不能直接视为运行时每块都在使用。原图 L1 RAM 367.77 KiB、L2 990.87 KiB、DDR 14.31 MiB，另外缓存 272 KiB；64 KiB 是栈预留。DDR 大项是开发框架的容量和加载工作区：

| 原 DDR 大项，按截图近似值 | 占用 | 原因 |
|---|---:|---|
| 主音色资产 | 2.75 MiB | 结构按通用最大容量预留，并有 RAM 副本 |
| 引擎与音频状态 | 1.35 MiB | 大块工作区、通用渲染状态和重复 owner/事件池 |
| 未使用多状态 DNA | 2.88 MiB | 当前单 DNA 音色仍保留多状态容量 |
| 加载与初始化工作区 | 5.95 MiB | 文件读取、模型装配和初始化 scratch 常驻 |
| MCPS 记录 | 264.42 KiB | 性能测试数据，量产不应常驻 |
| 其他池 | 约 1.11 MiB | 其余通用对象与测试预留 |

截图还列有 crosscheck 218.57 KiB，它属于验证用途。仅把数组改成 static 或把 L1 搬到 DDR，并不会减少总 RAM。

## 已实施的结构改动

1. 增加 `VSL_FIXED_V10` 固定配置。当前唯一音色离线编译为只读 C 系数，移除运行时文件加载和多份模型装配 scratch。生成器可重跑，未放 PCM。
2. 当前单锚点和单 DNA 只保留实际容量；删除没有使用的多状态资产与运行状态，不预留其他目录的音色。通用导入和多状态版本保留在非 fixed 构建中。
3. 取消 `VsEngine` 内重复 owner、事件池和不用的空间/IR/旧 residual 大缓冲，保留实际独立运行实例。fixed 只支持 source-only，空间渲染和 legacy 通用渲染入口显式拒绝。
4. 相干低频 profile 仅存实际 7 阶：88,392→2,004 B；保持原运算顺序，不删当前有效阶数。
5. 启动的 3 份 `SfProfile` 直接引用只读结构，取消约 12.4 KB 初始化 RAM。6 条启动 FIR、全部 3,072 个系数字面量逐一保留；连同怠速总共仍有 8 条 512-tap FIR。
6. 内部工作区改为 64 帧，对外仍接收 0～1024 帧并按顺序拆分，不改变时钟、随机流、控制采样和状态推进。
7. 保留 DNA 的 mean/left/right 热缓存，只删未使用的 unit 副本约 5 KB；单锚点取消跨锚点 sine 表约 16 KB。完全删除热缓存的试验曾显著拖慢 PC，已撤回，未交付。

仍保留主 DNA 300 阶 / 12 components、13 条模态、RDT 8 bands 和原滤波阶数、8 条 512-tap FIR、四事件声部、启动/行驶/回火控制以及 16 stems / 23 channels。当前 V10 的声音参数和实际有效容量没有降低。

## 验证

- MSVC 2022 FP32，实际改动编译使用 `/W4 /WX`。fixed 两项检查、generic 九项检查全部通过。
- 12 个工况：启动、怠速、加速、巡航、高转、收油、制动、换挡、停车、36 秒全流程、取消/重启、四声部事件；另有 air 扫动、air=0，以及 73/256 分块，共 16 组比较。最终 DLL 与原 V3 的混音及全部 23 声道逐样本一致，最大误差为 0；driver/event 记录去除计时字段后相同。
- fixed 合约测试覆盖第二实例拒绝且不破坏第一实例、close/reopen、0/1/64/73/240/1024 帧、超长和重叠请求无副作用、23 声道重建及四事件槽。重建浮点求和误差 1.49e-8 FS。
- 固化资产最初与原版完整 2,887,712 B 的 AtAssets 比较，规范化内部指针后零差异；最终两个生成器都可重新生成与交付文本一致的系数。启动所有 3,072 个 FIR token 保持相同。
- 正常 fixed 入口走静态槽，未发现可达堆分配；只读资产释放为空操作。检查到明显最大初始化局部数组约 5,120 B；这不能替代目标完整调用链的栈高水位。
- 强制四事件饱和测试可超过 1 FS，优化前后相同；这是用于压力验证的输入，不能据测试通过声称所有参数组合无削波。

音频详细收据、内存 JSON、生成器收据和 PC map 随桌面包提供。验证对象只绑定上述 SHA 的 memory-v1 DLL，没有混入同时进行的其他共振音色修改。

## 运算成本

本次主要降低内存。保留热缓存后的 3 组交替配对 PC 测量，每组 3 秒音频：

| 工况 | 耗时配对变化中位数 | 配对范围 |
|---|---:|---:|
| 怠速 | +0.97% | -3.27%～+1.97% |
| 启动 | -0.87% | -6.57%～-0.64% |
| 四事件压力 | +1.97% | -4.17%～+4.98% |

正值表示更慢。PC 的中位变化约 -1%～+2%，不作为 ADI MCPS、峰值或零开销承诺；板端应重新测总峰值及每模块成本，尤其留意 L1/L2 布局变化。用户之前的 1174.11 MCPS 是前一版实测，不能写成本次内存版的测量值。

## 构建与复验

```powershell
./build.ps1 -Mode compact -Test
python tools/check_memory_budget.py build/compact/bin/Release/vsl_source_bridge.dll --stack-bytes 65536 --io-bytes 2048 --budget-bytes 600000
```

`production` 保留原 V3 生产配置；需要本次内存配置必须选 `compact`，或 CMake 设置 `-DVSL_FIXED_V10=ON`。通用检查可用 `./build.ps1 -Mode generic -Test`。不要将任意旧 `bin/pc_x64` DLL 当作 compact 产物。

离线重生成：generic 构建产物 `compile_fixed_assets.exe` 在源码根目录执行，其 stdout 写入 `embedded/fixed_assets.inc`（使用字节输出避免 PowerShell 编码改写）；`python tools/compile_fixed_startup.py` 生成启动只读 profiles。改变音色参数后，必须重新生成、全量编译并重跑声音和内存验证。

目标集成步骤见 `../内存版_板端接入.md`。还需要 CCES map＋栈高水位＋无插桩 MCPS，才能对 ADI 600 KB 门槛做最终验收。
