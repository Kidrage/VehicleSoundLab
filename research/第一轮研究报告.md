# 纯 OSC 车辆声浪：第一轮研究与可运行原型

日期：2026-11-09。目标经你确认：自然吸气兰博基尼 V10，高转速、尖锐、车外／尾排附近。用户批准 A + B 后才开始下载和清洗。B 使用你随后提供的本地 MP3，已校验并移出桌面。

## 目前能下的结论

**纯 OSC 在原理上可以非常接近真实发动机的调性骨架；有限数量、固定频率比、只随 RPM 变调的 OSC，不足以保证真实车辆全过程的音色。** 纯 OSC 如果允许大量独立、随时间变化的幅度、频率和相位，可以继续逼近复杂信号，噪声与瞬态也能用很多正弦表示。因此“数学上不能”并不成立；真正的问题是模型效率、控制维度、相位与瞬态精度、运行成本和听觉相似度。

更实用的方向是保留你的三层结构：DNA 用同步阶次与动态频谱包络承担身份，PAD 小剂量承担车体／低频连续感，NVH 层用有统计结构的激励与瞬态承担粗糙度。共振和 IR 应作为有明确传递关系的处理模块，不靠叠加混响弥补声源模型。PAD 太强会掩盖 V10 的分辨度；噪声太多也会把尖锐声线糊成风声。

当前 C 原型验证的是架构、实时控制和可重复性，**还没有达到“与这辆 Lamborghini 听感一致”的验收状态**。没有进行盲听测试，也没有一个可信的“还原百分比”。V8 与 911 Turbo 还没有独立实测；911 Turbo 是水平对置六缸，不能把 V10 的映射直接改缸数就视作复刻。

## 为什么“差点意思”不能只看平均频谱

分析 A 道路尾排片段，按 8192 点 Hann 窗、1024 点 hop，选取每帧最强局部峰及其 ±2 FFT bin 主瓣，计算 80 Hz–16 kHz 能量覆盖：

| 峰数 | 全频段主瓣能量覆盖中位数 | 1.2–16 kHz 覆盖中位数 |
|---:|---:|---:|
| 4 | 78.8% | 0.0% |
| 8 | 88.0% | 0.0% |
| 16 | 93.7% | 23.1% |
| 32 | 97.0% | 61.3% |
| 64 | 98.7% | 85.4% |

这是**乐观的频谱主瓣能量统计**，选中的主瓣包含了邻近能量，且峰可以逐帧自由变动；它既不是 16 个固定 OSC 的能力，也不是音色相似度。数据说明低频很容易支配总能量指标，高频细节则可能被忽略。全局指标进步并不保证更好听。

还做了一个真正的离线振荡器实验：4096 点 Hann 窗，256 点 hop，在 80 Hz–14 kHz 内做峰值频率细化、相邻帧匹配、幅度插值和三次相位插值，分别用最多 16 和 64 条轨迹生成波形；没有加入原音频播放或噪声层。已知两个非整数 FFT bin 频率的正弦作为对照，重建残差约 −58.09 dB，验证了基本幅相链路。

| 实验 | 波形残差相对参考能量 | 含义 |
|---|---:|---|
| 16 条 OSC 轨迹 | −10.00 dB，约 10.0% | 同片段拟合，仍存在误差 |
| 64 条 OSC 轨迹 | −11.11 dB，约 7.75% | 高频频谱更接近，仍不是完全复现 |

残差包含峰值估计、跟踪、瞬态、相位、分析频段限制和噪声等多种误差，不能叫“噪声占比”，不能当作纯 OSC 的能力上限，也不能直接转成听感评分。这是**对同一片段的重建**，尚未证明对任意 RPM / 负载的生成能力。试听文件用中心窗口的非加权 RMS 对齐，再统一留峰值余量，不冒充 LUFS 匹配。

## 旧 Max 原型的检查

检查固定在公开仓库提交 [`ac2b37d…`](https://github.com/Kidrage/VehicleSoundSynth/tree/ac2b37d8639027d79934a2023cf8d1d37d3b2f96)，仅取文本源码。没有运行或改写 Max 工程，没有把原仓库的音频资产下载到本原型运行时。

1. **IONIQ6N 的定位与 V10 不同。** `root = 52 + 0.047 × RPM` 加上 1.5、2.25、3.05、5.37 等频率比，是一种设计音色。它可以好听，但不能直接当作 V10 燃烧阶次模型。非整数关系本身并不错误，适合的机械侧带、模态和电机音色都可能需要它；是否采用应由参考和审听决定。
2. **此前提到的频率限幅要收窄判断。** 仔细核对后，大多数独立上限在正常 RPM 范围内并不触发；只有少数低层项在接近 10000 RPM 的极端端点才触及上限。因此没有证据把这些 clamp 当作“版本越来越难听”的直接原因。
3. **时间常数应明确为毫秒。** Gen 的 `slide` 参数以采样点工作；例如 60 点在 48 kHz 约 1.25 ms，180 点约 3.75 ms。仓库目标 JSON 中有同名 60/180 ms 的 follower 描述，但这个 Gen codebox 的数值不等价于这些毫秒值。完整链路还有其他平滑，不能只凭单个节点断定实际响应；不过这是需要逐层测量的单位风险。
4. **音色状态不只在生成器。** README 明确写了 BEAP 文件首次生成后保留用户修改，并存在 ignored local preset；同一生成器可能搭配不同本地文件和模式状态。没有保存这些状态和校验值，就难以复现“上次好听的版本”。
5. **公开历史不足以做听感退化归因。** 查询 IONIQ6N 关键 Gen 和 DNA 图的公开路径历史，只返回添加该模块时的提交 `ba830a88…`。没有获得你听过的各修订源文件／预设／导出 WAV，不能宣布已经找到了退化根因。

新原型采用固定种子、固定测试驾驶曲线、预设 sidecar 与源文件／音频哈希。后续音色更改应新建版本，保留旧音频，在同参数、同参考、相近响度下比较。

## C 原型与边界

核心是 C11，界面是原生 Win32，48 kHz stereo，启动静音。三层独立，支持纯 OSC、手动 RPM / LOAD、固定驾驶曲线、WAV 导出／回放、预设保存／加载、用户谐波 DNA 和短 IR 导入。逐样本路径没有文件读取或动态分配。

DNA 用四冲程 720° 周期的 Fourier 系数表示燃烧事件；`f_fire = cylinders × RPM / 120`。V10 为 5 阶发动机主点火频率，6000 RPM 对应 500 Hz。缸列时延、幅度差与包络允许其他阶次存在，不能要求每个谱峰都恰好是 500 Hz 的整数倍。最高分音接近 Nyquist 时渐隐，使用统一周期关系，系数变化平滑。当前共振／气缸参数都是工程设定，未按 Lamborghini 转速与负载标定。

PAD 是可控的曲轴关联低频层；NVH 是噪声与调制激励近似，尚不是有限元车身模型；空间默认是合成短反射核，尚不是实测车厢 IR。输出当前为兼容 mono 的双 mono 基线，未把 B 的双耳空间映射到运行时。IR 导入最多 8192 帧，长混响需要分区卷积。Windows 后端使用默认 waveOut，未承诺专业 ASIO 低延迟。

已验证：CMake / MSVC Release 构建；确定性与音频块大小无关；稳定纯 OSC 不随噪声种子变化；输出有限且有边界；高频分音带限；Unicode 路径；WAV→DNA→C OSC→WAV；本机 waveOut 打开和缓冲提交；WAV 导出；界面实际显示检查。数值测试不能代替音色验收或实车验证。

## 下一轮建议

先在同一尾排片段上试听原音、16 OSC、64 OSC，再听 C 工程基线的纯 OSC 和三层版，指出最突出的差异是声线、颗粒、轰鸣、动态还是空间。要做可控的真车音色，下一步应采集／标注 RPM × 负载的阶次幅度、固定共振与瞬态状态，保留未参与拟合的验证片段。当前短片没有可信的绝对 RPM / 负载，不能把猜测写成车型参数。

你的 Serum / Logic 音色路线可行：稳定谐波快照已经能转成 `.dna` 并由 C 振荡器重建；复杂 Unison、包络、FM、噪声和调制需要多状态或独立模块，不能承诺仅凭一个 WAV 自动还原整个合成器 preset。建议先提供干声、固定根音与几档宏控制渲染，明确 DNA 的可变维度，再逐步加 PAD 与 NVH。
