# 应用0.19.1：键盘选择与界面核查

本轮修复原生驾驶界面的键盘输入冲突：踏板模式下，主消息循环曾在下拉框处理字符前截获S，使音色列表的SCI-FI字母查找变成刹车操作。新的独立输入路由保留控件的字符输入，也保留已按下踏板在焦点切换后的松键。应用版本为0.19.1，DSP、音色、驾驶算法与take格式继续为0.19.0。

## 使用

双击 `Launch-current.cmd` 或 `Launch-ui.cmd`。驾驶区域继续使用W／S油门／刹车、Q／E换挡；音色／模式下拉框拥有焦点时，字符和方向键交给该控件。切换焦点后松开已经按下的W／S，踏板仍释放；应用失去激活时也清除键盘踏板。

原应用入口 `Launch-v019.cmd`、`Launch-main-pressure.cmd` 保留。新旧应用都使用严格DSP0.19.0／schema4／36字段take，可相互读取，不修改文件头。V018及更早take仍需要对应旧DSP。

## 空白下拉框的实际原因

先将冻结V019二进制复制到独立诊断沙箱，以可见窗口执行原有静音设备检查，避免覆盖历史证据。真实画面显示V10与Pedal driving文字正常，说明此前隐藏窗口截图的空白不是用户界面的真实显示缺陷。

隐藏COMBOBOX的WM_PRINT没有绘出owner-draw选中项。诊断捕获现在读取该控件真实选中项与原生rcItem，并调用同一个父窗口WM_DRAWITEM绘制路径，不手写另一套标签。新隐藏截图与实际可见窗口均已目视检查。

旧可见截图：`experiments/ui_display_v1/legacy_sandbox/renders/v0.19.0/ui_ready.png`。新隐藏截图与实际字符选择截图：`renders/app0.19.1/ui_ready.png`、`ui_input_type_search.png`。

当前工具列表没有computer-use技能所需的node_repl入口，因此采用应用自身的窗口捕获和内部消息循环检查。没有调用系统SendInput、操作其他窗口或据此宣称完成物理键盘测试。

## 模块与版本

| 文件 | 职责 |
|---|---|
| `src/app/driver_keys.c/.h` | 将Win32按键消息分类；combo／list／edit保留字符；已按下踏板可以跨焦点／模式释放；重复换挡按键不连续触发 |
| `src/app/ui_input_check.c/.h` | 仅测试本应用的排队按键、原生字符处理、控件通知及踏板释放，不注入系统输入 |
| `src/app/version.h` | CMake提供应用版本；DSP身份继续由core/types.h定义 |
| `src/app/main.c` | 调度输入动作；回放期间不应用现场快捷键；诊断捕获选中项 |
| `src/app/take_smoke.c` | 仅把输出路径移至应用版本目录，重建算法不变 |
| `tests/test_driver_keys.c` | 原生控件类型、窗口范围、释放、模式禁用和重复换挡契约 |

相对冻结V019，既有源码／测试／CMake只有main.c、take_smoke.c和CMakeLists.txt改变；新增上表模块与一个测试。core、drive、profiles、spatial、session、io和原有测试源码哈希全部保持一致。不同构建目录下的lib／EXE不要求文件哈希相等，以源码身份和实际take输出验证DSP兼容。

应用构建目录为 `build-app0191`，诊断目录为 `renders/app0.19.1`，原V019构建与证据保留。应用和DSP版本分别维护，避免界面修复造成不必要的录制协议分裂。

## 验证

- 22项CTest通过；新增原生输入测试通过真实Win32控件类检查输入归属、无关窗口隔离、禁用模式、松键与换挡重复保护。
- 实际应用消息循环通过：S选SCI-FI且不刹车、模式列表中的E不换挡、W／S驾驶动作、焦点切换后松键释放，以及失去激活后释放。它包含TranslateMessage、原生COMBOBOX字母查找和父窗口选择通知。
- 实际waveOut静音运行1006块／515072帧：平均1.8555ms、最大4.9656ms；512帧预算10.6667ms。设备10.7307s／墙钟10.8549s，队列耗尽0。
- 设备take回放平均1.8691ms、最大4.7954ms；设备10.7307s／墙钟10.7574s，队列耗尽0。完整驾驶、character、response与event_color状态及离线／设备重建指纹一致，指纹为 `1081a7c566c20cb3`。独立实时录制的指纹不要求与前一版另一次录制相同。
- 冻结V019 take与本次新take，各自交给新旧两个实际渲染程序：两组float WAV和完整trace均逐字节一致，双向兼容。
- 实际预设往返、控件隔离、回放锁定和中途停止检查继续通过。原V019二进制与此前36份快照manifest身份保留。

主要证据为 `renders/app0.19.1/verification.json`、`ui_input.json`、`ui_smoke.json`、`ui_take_smoke.json` 与截图。校验脚本 `tools/verify_app0191.py` 拒绝覆盖完成数据；冻结在 `baselines/app0.19.1/manifest.json`。

本轮改善操作与验证准确性，没有新增音色候选或素材。原有逐次燃烧／机械细节、主排气变化仍待主观听评；目标车标定、整体自然度和实际7.1.4阵列听评仍未完成。
