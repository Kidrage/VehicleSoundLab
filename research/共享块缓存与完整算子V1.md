# 共享块缓存与完整算子 V1

这轮解决离线提取时同一计算块反复编译的问题，并核查完整288阶／73节点／双声道的共用计算方法。**这仍是已知信号上的工程验证，没有生成新的车辆音色。**

## 结构

声源数学定义继续使用 `vsl.shared-rounded-source-observation/1`。新增 `vsl.synthetic-shared-block-store/1` 只保存已知合成信号的频谱计算块，不保存原录音循环或驾驶声源轨迹。

| 模块 | 职责 |
| --- | --- |
| `tools/shared_basis_store_v1/identity.py` | 绑定全部几何、载波、校准、源码和FFT运行库身份 |
| `resources.py` | 在生成前检查完整磁盘／数组预算及余量 |
| `writer.py` | 编译与同步写入，全部完成后才发布目录，拒绝覆盖 |
| `reader.py` | 一次读取一个块，检查完整性、支持参数槽、头部与数据哈希 |
| `study.py` | 原始已知案例与执行源码的证据捕获 |

正向与转置读取相同的64位数据，左右声道保留独立系数和相位；零空间参数槽也保留。每个文件的形状和长度在分配数组前检查，尚未发布或身份不符的缓存不能进入计算。上述模块全部用于离线分析，不进入实时C回调。

## 已执行核查

四个原有小型案例的 **2,622,720个矩阵数值逐项一致**，完整声源／正向／转置／目标分组／梯度输出也与已独立核验版本一致。新的独立审核通过；14种缺失、截断、头部／数据损坏、运行库／校准／几何身份不符、资源超限和覆盖情况实际触发拒绝。

首轮 `known1` 因Windows不能对只读描述符执行同步而失败，保留当时源码、未发布目录和错误。`known2` 使用可写描述符同步清单后完成，失败记录没有重写。

完整测试仍用此前保存的已知信号输入，保留18,430采样点、73节点、288阶、84,096个实未知数、全部56观察窗／40目标窗和原校准。没有重新生成旧参考，也没有真实素材拟合。

完整独立审核已终止，**尚未整体通过**：共检查2,489,672个元素，正向、转置、各目标组和原始FFT对照通过；梯度与旧方法保存参考的相对差 `1.97479318540425e-8` 超过原 `2e-11` 门槛。保留这项失败，不重算缓存、不放宽门槛。原17项直接指标已重算；合成已知信号通过保真不等于真实车声或持续统计通过。

整个缓存只在E盘保存一份。归档包含不可变清单、哈希、执行源码和输出证据，避免重复存储18GB数据；没有复制真实D盘提取因子。数组预算不覆盖完整求解器，实测耗时也不是ADI或实时C的运行成本。

缓存复用确实省去了重复编译，但本机逐次读取与校验整批块仍很慢。下一步需要把快速候选迭代与最终完整核验分开：可评估已有FFT路径作为近似候选生成器或预条件器，最终约束、梯度／对偶和原波形／FFT指标仍由明确的共用列和原始观察契约核验。不能把快速路径的收敛当作精确路径通过。
