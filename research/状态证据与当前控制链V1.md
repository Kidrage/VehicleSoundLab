# 状态证据与当前控制链 V1

当前系统已经沿用 V6 的控制→状态→分层／事件→声源→空间方法，生命周期、工况、供给和换挡分别维护。各声层会随状态改变比例、谱形与响应速度。**这些工程参数尚未成为 Lamborghini 实测状态表。** 本轮只补充可审阅的证据索引，没有调整音色或驾驶参数。

[交互审阅页](状态证据审阅V1.html) 可以切换视频情境、从指定源时间播放，并查看由冻结 C 库直接导出的八工况 × 六声层系数。视频无声；音色继续在已有试听页评价。

## 当前代码与证据的对应

| 控制轴 | 当前职责 | 参考证据能支持到哪里 |
|---|---|---|
| `drive/lifecycle.c`、`profiles/lifecycle.c` | OFF／READY／CRANK／CATCH／RUNNING／STOPPING；连续 flare／settle | 有启动操作语境；拖转、接火、停机时序未实测 |
| `drive/drive.c`、`profiles/voicing.c`、`core/orchestrator.c` | 八工况、六层独立响应、谱形与切断／恢复 | 驻车／运动／录音视角可确认；工况阈值、层比例未实测 |
| `drive/shift.c`、`drive/clutch.c`、`profiles/transmission.c` | 断开／匹配／接合，独立内部补油；运动模式松油保挡 | 现有画面不能标定这些阶段的精确时序 |
| `drive/fueling.c`、`profiles/fueling.c`、`core/excitation.c` | OFF／FIRE／DELAY／CUT／RESUME；燃烧与泵气支路 | 声音能量下降不证明喷油关闭 |
| `core/events.c` | 有条件的收油连击、换挡事件及起动机声 | 事件配方和触发窗口仍为工程设计 |

表中代码路径均相对 `src/`。模块的 SHA256 绑定在 `evidence.json`。上游继续使用已核实的 V6 提交 `ac2b37d8639027d79934a2023cf8d1d37d3b2f96`；没有将其 Ferrari V10 参数当作 Lamborghini 测量值。

冻结库的只读 C 导出器在 `experiments/state_context_v1/`；输出 `runtime_tables.json`。它确认五个模板目前共享工况层次与响应配置。比如排气／机械换挡抑制深度分别为 1.00／0.18，切断响应时间分别为 12／45 ms；完整声压还要叠加负载、生命周期、供给及平滑包络。不能只看工况表中的 1.00 就认为该层没有换挡变化。

现有三条冻结 take 的音频时钟轨迹合计出现了八种运行工况、五种供给状态、四种换挡阶段。索引见 `native_trace_index.json`。这是实际模型状态记录，不是视频识别结果，也不表示这三条 take 覆盖了全部生命周期与安全边界。

## 验证与下一步

核对了帧 PTS／区间／哈希、已批准原音和 float32 主文件、原生 144 个源码与控制契约文件及相关二进制。浏览器实际执行六情境跳转、静音视频播放、区间末端停止、八行 C 系数切换，并检查桌面／手机布局；结果见 `verification.json` 和 `browser_qa.json`。原生 DSP 没有变化，本轮不重跑与改动无关的声学测试。

当前可继续做的是同一录音视角下的条件声形观察。精确启动／换挡／断油时序还缺可信的控制或遥测证据，本轮不据此重拟合参数。逐次燃烧、机械细节及主排气谱形的候选仍等听评；数值验证和画面核查均不作为主观真实度验收。
