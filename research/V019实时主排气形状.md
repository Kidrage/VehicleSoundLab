# V019：实时主排气逐次形状

这轮将已冻结的 `event_color_v1` C 候选接入原生驾驶程序，对应用户“整体都偏电子：先加强逐次燃烧与机械细节”的方向。新增独立控件可实时调节、保存预设、录制和回放。它默认关闭，尚未获得主观认可；V011连续排气谱形与V018入口保留。

## 操作

双击工作区 `Launch-current.cmd` 或 `Launch-main-pressure.cmd`，按 Start 开始监听。在 Sound detail：

1. 选择工厂V10，关闭 Pure OSC，勾选 Per-firing pressure variation；Cycle irregularity 可先用默认35%。
2. 先保持 Combustion texture、Mechanical transfer、Response shape 三项实验旋钮为0，单独比较右下角 Main pressure shape 的0／50／100%。
3. 优先在相同负载的4000／8000 RPM台架比较，再听实际给油、收油和换挡。100%代表完整候选深度，不代表最真实。
4. 需要组合时再增加逐次压力／机械层；主排气旋钮不依赖这两层的强度。New take录制驾驶和调参，Save take／Play take保存与重放。

新参数 `event_color` 默认0，旧预设缺字段也回退到0。旋钮使用18ms逐样本平滑，事件控制另有1.5ms平滑；实时归零仍有平滑、滤波和IR尾音。新会话从0开始与V018完整输出精确一致。

保留 `Launch-v018.cmd`、`Launch-response-shape.cmd`（V018）、`Launch-v017.cmd`、`Launch-character.cmd`（V016）和 `Launch.cmd`（V015）。V019 take为严格DSP0.19.0／schema4／36个显式语义字段；V018为DSP0.18.0／schema3／35字段。旧take用对应冻结二进制回放，不重写文件头。

## 算法与维护

| 文件 | 职责 |
|---|---|
| `src/core/event_split.c/.h` | 两个固定二阶Butterworth低通及其历史 |
| `src/core/event_color.c/.h` | 读取已有逐缸事件，管理两缸列控制、许可、旁路和主燃烧声增量 |
| `src/core/event_color_types.h` | 每引擎独立滤波／控制／延时状态和计数器 |
| `src/profiles/event_color.c/.h` | 分频、平滑和变化深度，独立工程配方 |
| `src/core/engine.c` | 在原主压力生成后保存该支路，附加细节之后／原IR之前调度候选 |
| `src/session/parameters.h`、`src/io/take_file.c` | 显式参数、严格版本与文件校验 |
| `src/app/tuning.c`、`preset.c` | 独立旋钮及预设，单次操作只修改对应参数 |
| `tests/test_event_color.c` | 原生模块契约、状态与实际分块／布局一致性 |

令 `x` 为原低DNA与高阶OSC经过燃烧供给增益后的主压力，`l=LP1400(x)`、`u=LP4500(x)`：

`y = x + 0.45 m_mid (u−l) + 0.90 m_high (x−u)`

每次许可燃烧事件沿用已有逐缸energy／shape状态：

`target_mid = 0.65 energy + 0.35 shape`

`target_high = −0.20 energy + 0.80 shape`

控制经1.5ms平滑后，乘旋钮力度及裁剪到0～1的 `irregularity/0.35`。右缸列控制使用原0.38ms工程延时约定和分数采样插值；不是由录音左右声道识别缸列。两个低通的差分有重叠和相位，不是理想砖墙频带。

不增加随机数、不改变原曲轴或事件调度。共享 `vsl_fueling_allows_firing` 许可；停机／断油后不接受新燃烧事件，控制释放，原旋转机械和已有振铃继续按原模型推进。其他模板、导入DNA、Pure OSC或关闭原逐次压力模型时旁路。

增量只作用于原主燃烧支路，泵气和新增压力／结构声保留原路径。改变后的排气仍进入原有DNA驱动IR，因此其body返回也会变化。主路径没有参考录音播放。V6的驾驶→状态→独立声层／事件→空间方法继续沿用；上游固定修订为 `ac2b37d8639027d79934a2023cf8d1d37d3b2f96`。

## 实际验证

- 21项CTest通过。新增测试覆盖范围／平滑／有限值、原驾驶／DNA／高阶／逐缸随机／响应／NVH完整状态、停机事件许可、1与257帧分块、stereo／12声道十源状态，以及模板／导入／Pure OSC／压力开关旁路。
- 实际waveOut静音运行1006块、515072帧：平均渲染1.8842ms、最大5.2438ms；512帧预算10.6667ms。设备10.7307s／墙钟10.8533s，没有队列耗尽。这是本机一次检查，不是所有机器的性能保证。
- 同一实际take设备回放平均1.8807ms、最大4.3468ms；设备10.7307s／墙钟10.7544s，没有队列耗尽。11个输入变化，音频指纹 `a5adca370b70f5ed`；完整character／response／event_color状态、驾驶状态、离线／设备音频重建均一致。
- 五模板默认WAV与V018逐字节一致。七场景分别生成各自版本的新take；主排气旋钮0时，float WAV与V018逐字节一致。旋钮0／100%的原日志全部列和事件计数一致。
- 原生100%与冻结静态候选在2.5s之后比较，最大float差为 `7.28e−12`，低于 `1.2e−7` 容差；该区间避开静态原型初值1与原生18ms起始平滑及已有响应尾音的区别。
- 实际带调参take的stereo／7.1.4十个声源逐字节一致，完整日志一致；stereo离线WAV与设备检查所用重建WAV一致。实际扬声器阵列听评尚未完成。
- 实际控件隔离、精确非网格预设往返、旧预设字段回退、回放锁定、手动停止通过。细节页截图已检查，新旋钮完整显示。
- V015／V016／V017／V018二进制哈希保留；V011的四个排气声线文件一致；此前34份冻结manifest身份保留。

## 复现与证据边界

```powershell
.\build.ps1 -BuildDirectory build-v019
.\build-v019\Release\VehicleSoundLab.exe --smoke-test
```

`tools/verify_v019.py` 生成七场景的实际新take与WAV、布局对照和源码／二进制身份检查；它拒绝覆盖已完成验证。`--audit` 检查工作区产物，`tools/freeze_v019.py` 只冻结通过审计的版本。结果在 `renders/v0.19.0/verification.json`、`workspace_audit.json`，冻结清单在 `baselines/v0.19.0/manifest.json`。一次性迁移脚本 `tools/integrate_event_color_v019.py` 不应重跑。

没有新增素材下载或物理标定。energy／shape、滤波分频与调制深度是工程配方，不是实测缸压、机体FRF或排气系统参数。时变增益会产生调制边带，尚未证明所有参数／采样率下严格带限。

主排气候选比附加响应形状带来更大波形差异，可能增加粗糙感；数值一致和操作可用不能证明电子感下降。已有逐次形状试听问题仍待反馈，不重复提问或推断接受。目标车RPM×负载标定、整体自然度和实际7.1.4听评尚未完成，整体目标继续进行。
