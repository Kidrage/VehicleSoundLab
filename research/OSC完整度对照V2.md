# OSC 完整度对照 V2

**后续听评：细节保留版明显改善，录音参考正常。** 已固定 `rank64` 为重建质量参照，身份与范围见 `research/timbre_quality_20261110.json`；独立[原生 C 监听](细节OSC原生监听V1.md)默认与该试听文件逐样本一致。以下测量与诊断边界保留，原冻结快照仍记录当时待听评状态。

2026-11-10。用户对上轮“短窗联合拟合 · C”的明确反馈：**原来的低质／压缩感基本没变**。该候选未通过听评。长窗损失和匹配问题虽经数值测试确认，现有听评不足以支持把它们认定为主要听感原因；上轮误差改善也不应被描述为音色问题已解决。

本轮以[简洁对照页](OSC完整度对照V2.html)检查信息完整度。目的：判断更完整的正弦／余弦 OSC 表示能否保住原录音质感，明确稀疏重建与原录音坐标各自的边界。高频增强继续暂停。

## 对照方法

输入是上轮已经发布的 `band_only_audition.wav`：历史六秒、显式单声道、80–14 kHz FIR 带宽控制，沿用旧版共同增益和端点淡入淡出。此输入 hash 与上轮报告一致，源 A raw／float 主文件再次经目录核验。

新方法用 512 样本（10.67 ms）周期 Hann 分析、128 样本步长。每帧复系数对应固定频率的正弦／余弦 OSC；C 用递推振荡器逐样本求和、Hann 包络交叠相加。四帧的平方窗和恒为 1.5，用该常数还原幅度。C 合成器没有 FFT、音频文件解码或输入 PCM 读取。

| 选项 | 每帧保留项 | 同时重叠帧 | OSC 上限 | 用途 |
|---|---:|---:|---:|---|
| 较少 OSC | 最强 16 个频点 | 4 | 64 | 接近早期 OSC 计算量的完整度控制 |
| 细节保留 OSC | 最强 64 个频点 | 4 | 256 | 主要听评候选 |
| 完整 OSC | 全部 257 个频点，含 DC／Nyquist 项 | 4 | 1028 | 信息完整时的诊断上限 |

旧版“64”是每个分析帧最多 64 个谱峰，新生／结束时并行数另有增加；上轮联合拟合导出最多 98 行。本轮每帧 64 不等于总共只有 64 个 OSC，不能将质量变化全部归功于更聪明的同规模模型。

这里 Fourier 频点包含窗口泄漏及其相互抵消项，**不是分离得到的物理发动机谐波或气缸**。合成包络也会产生边带；表中是实现中的项数，不是可感知分音数量。

## 当前技术结果

- **完整 OSC 的 PCM24 试听文件与输入带宽录音逐样本一致**，最多绝对差为 0。原生 C 递推计算与 Python 独立 irFFT 控制一致，证明这条 OSC 表示／合成链本身可以保住该输入的信息。
- 每帧最强 64 项的波形误差约 −42.02 dB，每帧 16 项约 −18.32 dB；均相对于同一带宽录音，忽略首尾各 0.2 秒。此处只量化信息误差，不是自然度或真实感。
- 车外段 2.6–5.8 秒的未加权 RMS：录音 −22.838 dBFS、细节保留版 −22.838 dBFS、旧版 −23.184 dBFS。没有逐版增益补偿；旧版约低 0.35 dB，听评需知晓这一小电平差。
- 正弦递推 C 与 Python 的 raw float32 最大绝对差小于 1.5×10⁻⁸。独立已知非整频点 AM／扫频控制包含首尾，最大误差小于 10⁻⁷；截断模型和无效频点被加载器拒绝。
- 只修改独立 `experiments/osc_density_v1` 与离线工具，原生驾驶应用、音色核心和已冻结的监听窗口保留。

## 不能从这些结果得出的结论

完整 OSC 对照本质上是保留录音信息的可逆变换；它的密集、随时间变化的复系数相当于整段录音的另一种表示。虽然 C 运行时没有 PCM 样本回放，也**不能把这件事当成已经学会发动机发声规律，或已经解决任意 RPM／负载的纯 OSC 合成**。这项对照是有意设置的诊断上限。

此外，本轮同时改变帧长、频率选择、相位连接、包络交叠和表示容量。用户若听到改善，只能先说明这一整体信息保留方式更合适；不能单独认定“增加 OSC”或“去掉相位插值”就是唯一原因。

源文件曾经过 YouTube Opus、历史单声道混合及清洗；本轮保住的是这个明确输入。未经听评，也不能保证它已经等同于用户期待的原车现场质感。

## 本轮听评决定下一步

先比较主页面三个选项，优先 2.6 秒后。完整 OSC 作为与录音严格一致的交叉检查。

- 若细节保留版明显改善，而较少 OSC 仍差：继续分析需要保留的弱分量／调制结构，以及降低计算量的办法。
- 若录音听起来正常，但主候选仍差：检查其稀疏误差与听感的频带／时间分布，不能仅依赖全段误差。
- 若录音／完整 OSC 也有同样低质感：回查原生立体声、历史单声道、源编码与录音机位，停止把问题全部归咎于 OSC。

得到明确听评后，再提炼与相对音高、负载情境和状态有关的谱形／调制分布，形成持续合成模型；额外高频处理排在后面。

## 模块与文件

- `experiments/osc_density_v1/model.*`：有边界、顺序、数值与截断校验的离线系数加载器。
- `experiments/osc_density_v1/oscillator.*`：递推正弦／余弦求和与窗包络交叠。
- `experiments/osc_density_v1/probe.c`：独立离线 float WAV 导出。
- `tools/osc_quality_v2/bank.py`：频域分析、系数导出、独立 Python 逆变换控制。
- `tools/osc_quality_v2/render.py`：无覆盖的 C 渲染与一致性验证。
- `tools/diagnose_osc_quality_v2.py`：主实验、已知控制和加载失败检查。
- `references/analysis/osc_quality_v2/results.json`：参数、输入来源、数值结果、模型／试听 hash。
- `references/analysis/osc_quality_v2/verification.json`：历史素材、快照、原生源码和界面审计。

独立构建：`cmake -S experiments/osc_density_v1 -B build-osc-density-v1 -G "Visual Studio 17 2022" -A x64`，再 `cmake --build build-osc-density-v1 --config Release`。输出目录存在时，诊断入口拒绝覆盖旧结果。旧 V1 实验完整保留，新实验另冻结为 `baselines/osc_quality_v2`。
