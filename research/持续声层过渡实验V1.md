# 持续声层过渡实验 V1

本轮确认并实现了一个独立的控制过渡修整：将七个持续声层音量控制从 200 Hz 保持改为逐样本因果线性过渡。没有修改原生 V016、V011 主声线、工况配方或逐次燃烧／机械候选的参数。

结论是：控制阶梯确实存在，插值也按预期减小了设计载波的控制镜像；但四段完整混音的新旧差值 RMS 比原混音低约 44～47 dB。现有证据不足以将它视为整体电子感的主要原因或主要解决办法。保留为独立实验，不接替默认程序，不要求本轮听评才能继续其他工作。

可选入口：[持续声层过渡试听](持续声层过渡试听V1.html)。建议关注空挡补油／收油边缘，而非期待稳态音色明显改变。

## 算法与模块边界

对七个控制量插值：`dna_gain`、`body_gain`、`intake_gain`、`mechanical_gain`、`air_gain`、`high_gain`、`mechanical_motion_gain`。其他 voice 字段、状态混合、切断目标、谱形控制、燃烧时钟、供给门控和空间路径保留原算法。

令控制周期为 N，g[k] 为本次编排得到的原始目标。周期内第 j 个样本使用：

`y[kN+j] = g[k−1] + (j+1)/N × (g[k]−g[k−1]), 0 ≤ j < N`。

新引擎从 g[−1]=0 开始。它等价于对原来的保持包络做 N 点等权因果 FIR；只用过去值与已经到达的当前目标，没有未来输入。48 kHz 时 N=240，包络的群延迟为 119.5 样本，即约 2.4896 ms。此延迟作用于七条音量包络，并非整段音频、曲轴、驾驶输入或换挡事件的整体延后。目标发生变化时，瞬态形状仍会因平滑而改变。

编排始终使用原来的控制状态；仅在音频生成过程中临时发布插值音量，生成后恢复原始 voice。这样下一次编排不会将插值值当成自身历史，避免改变原有 attack／release 轨迹。

| 文件 | 职责 |
|---|---|
| `experiments/gain_bridge_v1/bridge.c/.h` | 独立七路插值、控制目标与测量统计；逐样本路径无分配或文件 I/O |

| `checks.c` | 独立闭式插值、精确旁路、控制不变性、布局和分块检查 |
| `tools/render_gain_bridge.py` | 渲染、原版指纹、独立 FIR／载波检查与共同增益试听 |
| `tools/seekable_review_player_v1.js` | 本地可定位播放器，与 DSP、页面数据分开 |

## 观察与验证

四个场景均重放已冻结的输入，保持固定种子 48271。高转和自动挡使用已有燃烧／机械各 65% 配方，其他两段为零强度基线。两版共用每场景固定增益，没有分别归一化、压缩、EQ 或新淡入淡出。

| 场景 | 原混音 RMS dBFS | 两版差值 RMS dBFS | 差值相对原混音 | 共同试听增益 |
|---|---:|---:|---:|---:|
| 8000 RPM，各 65% | −29.279 | −76.21 | 约 −46.93 dB | +6.28 dB |
| 空挡补油／落转 | −37.170 | −80.90 | 约 −43.73 dB | +14.17 dB |
| 收油／供给切断／恢复 | −31.276 | −76.53 | 约 −45.25 dB | +8.28 dB |
| 运动自动挡，各 65% | −30.780 | −75.58 | 约 −44.80 dB | +7.78 dB |

差值包含完整确定性重渲染中的一切变化，含模态受击幅度和 IR 返回变化；不能称为被消除的噪声、独立点击能量或真实度改善量。整段指标还包含启动过程。8000 RPM 最后两秒的输出差值峰值约 `1.14e−13`，符合稳态目标不变的设计，但不能推广成所有工况都逐样本不变。

![C 增益与载波检查](../renders/gain_bridge_v1/gain_bridge.png)

左图取 `lift` take 中**最大音量阶跃附近的起动／接火过程**，不是截取收油边缘；右图为独立设计载波。真实收油／补油仍应在完整试听或日志中检查。

- 七路控制的最大单样本变化由原始控制阶跃分散至 240 个样本；实际 C tap 与 Python 独立等权 FIR 的最大误差约 `1.18e−7`，包含 float32 导出误差。这个 240 倍关系描述控制量，不是完整音频伪影的统一衰减。
- 48 kHz、200 Hz 控制、7 Hz 幅度调制、2048 Hz 载波、2 秒预热后导出 4 秒的设计测试中，第一对镜像的增益约降低 28.83／29.43 dB；7 Hz 主调制约变化 −0.0175 dB。结果与离散 FIR 闭式频响相符；不是实车频谱或拟合结果。
- 最初用 2000 Hz 载波，正负载波分支的控制镜像恰好重合，单一镜像公式验证失败。保留音频、当时源文件和独立复数频谱复算，位于 `renders/gain_bridge_v1/initial_carrier_overlap/`。改用两组镜像不重合的 2048 Hz 设计后通过；没有把原失败当成 bridge 算法或真实发动机随机性的证据。

验证覆盖：

1. CTest 通过。独立公式覆盖 N=80／221／240／480／960；五模板 × stereo／12 声道 × 旁路／插值检查中，旁路的完整 engine、音频和声源逐字节不变。开启时完整驾驶状态、原控制 voice、曲轴／导入时钟、DNA／高阶系数、事件状态和随机种子保持一致。1 帧与 257 帧处理结果一致。
2. 四个旁路完整 WAV 和日志、四十个原始声源与先前冻结导出逐字节一致。启用后完整轨迹只在机械存储能量及已启用 character 输出测量字段变化；驾驶、供给、控制目标等字段相同。事件、路噪、风噪源保持逐字节一致。
3. 8000 RPM 插值另导出 12 声道：十个声源、七组控制 taps 和完整日志与 stereo 逐字节一致。输出没有削波。7.1.4 坐标／通道来自 C；未做物理音箱阵列听评。
4. 浏览器实际静音解码／播放检查通过，覆盖八个普通对照、保留位置和播放状态、过期请求隔离、独立播放按钮、切场景复位、图像加载、HTTP／file 入口及窄屏布局。没有自动播放出声或主观听音结论。
5. 原生 144 个源码／测试／构建约定文件、原生二进制、四个 V011 主声线文件以及经批准原始／float 素材保持哈希一致。此前 26 份快照 manifest 身份记录在验证文件中；不是重审全部历史文件内容。

构建复现：

```powershell
cmake -S experiments/gain_bridge_v1 -B build-experiment-gain-bridge -G "Visual Studio 17 2022" -A x64
cmake --build build-experiment-gain-bridge --config Release --parallel
ctest --test-dir build-experiment-gain-bridge -C Release --output-on-failure
.\build-experiment-gain-bridge\Release\gain_bridge_probe.exe .\renders\v0.16.0\neutral_base.vsltake <新目录中的输出前缀> 1 2
```

固定目录完成后有覆盖保护。`*_gain_*.wav` 的 L／R 分别是保持控制值／插值控制值，属于诊断数据，**不是可直接当成声音播放的 stereo 音频**。试听页只引用明确的 PCM24 混音副本。

冻结入口：`baselines/gain_bridge_v1/manifest.json`；完整 float 混音、声源、控制 taps 和日志保留在原 `renders/gain_bridge_v1` 哈希绑定路径。总体目标中的真实 V10 声纹标定和主观验收仍未完成；当前优先方向仍是依据分层听辨，定位主排气事件形状或传递响应，而非将控制插值包装成音色升级。
