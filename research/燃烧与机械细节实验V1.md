# 燃烧与机械细节 · 独立实验 1

用户确认 V0.11 更连贯、更接近目标，同时指出两版都还需要加强音色。本轮优先项是“整体都偏电子：先加强逐次燃烧与机械细节”。完整意见单独记录在 [听评记录](听评记录.md)。

本实验保留当前 V015 主程序和 V011 排气谱形，在单独的 C 宿主里提供四种试听：基线、只增强逐次压力、只增强机械、两层各 65% 合用。打开 [试听页](燃烧与机械细节试听V1.html)，先比较 4000／8000 RPM，然后听补油和收油；四版可以在同一位置切换。每组共用一个明确的固定增益，保留实际电平差异。

## 为什么做这两项

V09 已有缸列压力的幅度和到达时间变化，但没有独立的有限时长压力响应。V08 的机械源虽然已经是“冲击—储能—衰减”，此前测量中在完整混音里仍比排气低约 40–51 dB。因此本轮检查压力的短促响应和机械的可听度；不把任意加大随机性当作真实度证明。

最新高频分析发现的恒负载气流控制问题继续保留为后续线索。用户选定的当前优先项是燃烧与机械，本轮没有修改空气层、排气的静态谱形、车辆或空间算法。

## 机制与边界

沿用实际积分曲轴的 720° 点火几何。每个缸保留独立固定种子及跨循环的事件强度／形状记忆。在采样间精确定位事件；同一次事件的有界强度同时驱动短压力响应和较慢的结构响应。代码中的 `event_energy` 是无量纲工程强度，不是测得的缸压、燃烧热量或焦耳。它们不会反过来改写曲轴、扭矩、换挡或原压力模型的随机流。

压力响应是三条受激阻尼正弦，不播放素材：1050／2900／6100 Hz，衰减常数 1.4／0.65／0.32 ms。逐次事件小幅改变各模态的比例，既有尾音继续叠加，不重新调谐或清零。两缸列保持独立声源，右侧继续使用单独的 0.38 ms 工程传播约定；实验延时采用一阶分数采样插值。以上频率、时长和幅度是**明确的工程试听参数**，不是从 A/B 混合录音分离出来的实车缸压或歧管测量。

结构响应由同一燃烧事件、当前排气压力包络和机械层控制包络共同驱动，另有 610／1180／2240／3870／5820 Hz 阻尼模态，衰减比压力更慢。机械增强量还把已有机械源最高放大到四倍幅度（约 +12.04 dB）；这个倍数直接记录，不通过独立响度匹配掩盖。机械层自己的原有曲轴冲击、转动随机流和断油旋转声保留。结构表仍是工程假设，不能把增强后的敲击声直接称为目标 V10 的机械特征。

新增事件只在 CATCH／RUNNING、供给允许且已有燃烧压力有效时触发。断油和 STOPPING 不再触发新的燃烧事件；已储存的短余振按自身阻尼衰减。Pure OSC、导入 DNA 和其他四模板均旁路实验。原生 V015 的燃烧变化／机械模型开关也分别约束对应实验分量。

新压力进入两个排气源并沿用 DNA→IR 返回，新结构进入独立机械声源。其他进气、气流、路噪、风噪和事件源不受修改；空间接收与激励分开。Stereo 和 7.1.4 使用相同的十条源和事件时序，7.1.4 仍是 speaker bed，尚未做真实阵列听评。

## 模块与复现

| 文件 | 职责 |
|---|---|
| `experiments/character_v1/character.c/.h` | 曲轴事件、逐缸记忆、资格条件及独立宿主绑定 |
| `pressure.c/.h` | 两缸列短压力响应与单独到达延时 |
| `structure.c/.h` | 燃烧驱动结构余振 |
| `profile.c/.h` | 明确的工程频率、衰减与强度 |
| `probe.c` | 读取冻结 V015 take、float32 混音、十源与三条新增分量导出 |
| `checks.c` | 来源独立、驾驶不变、事件资格、余振和布局测试 |
| `tools/render_character_review.py` | 六组相同 take × 四种设置、固定增益试听和数据核验 |

独立构建：

```powershell
cmake -S experiments/character_v1 -B build-experiment-character -G "Visual Studio 17 2022" -A x64
cmake --build build-experiment-character --config Release --parallel
ctest --test-dir build-experiment-character -C Release --output-on-failure
```

候选宿主链接冻结 V015 核心，在构建目录生成带一个对象处理挂点的调度器；源文件来自冻结副本，挂点位置有唯一性检查。主程序源码、二进制和 Launch.cmd 均不变。实验明确标记 `character_v1`，不冒充新的 V015 发布，也不把候选音频写成可以通过原 V015 指纹检查的 take。

现有 `.vsltake` 也可用于离线对照，例如：

```powershell
.\build-experiment-character\Release\character_probe.exe render .\performances\某次驾驶.vsltake .\renders\自选对照 0.65 0.65 2
```

最后三个参数依次为压力增强量、机械增强量、声道数；增强量范围 0～1，声道为 2 或 12。输出前缀须使用新名称；目标目录需存在。输入文件仍要求 V015 格式和版本。

## 验证与听评

`renders/character_v1/results.json` 保存六组参数、命令、音频／输入哈希、各源不变量与原电平指标。基线候选量设为零时，与冻结 V015 的 float32 take 重建逐字节一致。四种候选的完整驾驶日志与燃烧事件序列相同；组合输出满足对应分量的线性叠加，数值误差受 float32 舍入限制。7.1.4 的十条源与立体声逐字节相同。后续独立核验记录在 `verification.json`。

稳态 2.5～4.8 秒内，机械源相对两个独立排气源功率之和的比值如下。它反映实验实际力度，不是完整混音响度、物理声功率或真实度评分。

| 工程转速 | 基线 | 机械增强 100% | 两层各 65% |
|---:|---:|---:|---:|
| 1200 RPM | −43.29 dB | −25.61 dB | −28.92 dB |
| 4000 RPM | −52.76 dB | −27.83 dB | −31.56 dB |
| 8000 RPM | −53.76 dB | −29.35 dB | −33.10 dB |

这里验证的是实现和比较条件。尚不能由模式数量、逐次变化或层级响度推断自然度提升；请判断电子嗡鸣、敲击、振铃、毛刺和高转嘶吼的实际变化。通过听评后再决定哪些参数值得迁入主程序的新版本。
