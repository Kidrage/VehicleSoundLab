# 声源分层试听 V1

入口：[声源分层试听](声源分层试听V1.html)，或本地服务器 `http://127.0.0.1:8789/research/声源分层试听V1.html`。

本轮把已冻结的声音拆成可操作的听辨对照。没有新增音色配方，也没有将候选配方判定为更真实。主观电子感来自哪一条支路，仍需听辨。

## 操作

选择场景、既有配方和声源组，再切换 **完整混音／单独听／去掉它**。视图、配方和分组切换保留播放位置与播放／暂停状态；换场景停止并从零开始。单独的播放按钮方便窄屏操作。浏览器加载／定位会有间隙，不是逐样本无缝切换。

建议先用 8000 RPM，对照排气、机械和机体，再听空挡补油落转与自动挡。两套配方分别为 V016 的细节零强度基线，以及已冻结的燃烧／机械各 65%；后者仍未得到听感认可。V011 连续排气谱形保留。

机械独奏可显式开启 **额外 +24 dB**。默认关闭；离开机械独奏、返回完整／去掉、切换分组或场景时自动关闭。同一个辅助增益用于全部场景和两套配方，没有独奏归一化。辅助版本最高峰值约 0.461，未削波。此按钮用于听清细节，不能代表原位混音中的贡献。

每个场景的两套配方、15 个视图共用一个固定增益。以较响的完整片段 −23 dBFS 非加权 RMS 为名义目标，所有视图峰值约束为 0.85；没有 LUFS 匹配、限幅器、压缩、EQ 或新淡入淡出。场景之间不用于绝对电平比较。

| 场景 | 共用固定增益 | 基线机械独奏相对完整混音的 RMS | 各 65% 配方机械独奏相对完整混音的 RMS |
|---|---:|---:|---:|
| 4000 RPM 带载 | +7.23 dB | −49.58 dB | −29.67 dB |
| 8000 RPM 带载 | +6.28 dB | −51.27 dB | −31.46 dB |
| 空挡补油与落转 | +14.04 dB | −42.03 dB | −27.85 dB |
| 30 秒运动自动挡 | +7.78 dB | −43.34 dB | −25.78 dB |

这些是整段、空间渲染后、同一 master 的电平差。各组可能相关，不能把这些差值当作独立声能比例、可闻度或真实度。它们说明现有机械对象在完整混音中较轻，不能据此决定直接加大机械音量。

## 分组语义

分组发生在源端声音构建和 IR 返回之后，共有 7 组、覆盖 10 个声源对象。每组独立维护与原生相同的空间历史，保留视点、直达传播、低频、反射、宽度及输出高通。并非将 mono 分轨直接贴到左右声道。

| 分组 | C 对象 | 边界 |
|---|---|---|
| 排气 | exhaust_left、exhaust_right | DNA、高阶、泵气及已启用的压力细节；尚未再拆成逐激励独奏 |
| 机体 | body | PAD、源端短 IR 返回及已启用的结构机体贡献 |
| 机械 | mechanical | 既有机械模型与已启用的结构机械贡献 |
| 进气 | intake | 独立进气对象 |
| 气流 | air_left、air_right | 两路独立空间声源 |
| 瞬态事件 | events | 起动机、回火和换挡事件；片段内可能无事件 |
| 路噪／风噪 | road、wind | 两个环境对象；台架／驻车时可能无声 |

**去掉排气仍保留机体中已经形成的排气激励 IR 返回。** 因此这是声学对象的删除对照，不能解释成关闭排气激励后重算整个系统。只听机械也没有包含机体对象中的结构贡献。未来要定位因果支路，需要另做激励级实验，不能从本工具直接推断。

已批准 A 参考沿用既有低转 208–211 秒和补油 238–248 秒切片，来源、SHA256 和处理记录见 `renders/source_audition_v1/results.json`、`references/segments_v1.json` 及 `renders/exhaust_envelope_v1/results.json`。切片为原 stereo、固定 −6.0206 dB、5 ms 端点余弦淡化、PCM24；没有新下载或清洗，未与合成器匹配工况、响度或录音位置。参考与合成器播放互斥。

## 代码与复现

- `experiments/source_audition_v1/audition.c/.h`：分组、独立空间状态与视图输出。
- `CMakeLists.txt`：从冻结 V016 源码生成显式 observer 参数的调度／空间／take 副本，链接原封不动的 V016 C 库；不改原生文件。对象位置读取原生 `vsl_object_info`，没有第二套坐标表。
- `probe.c`：重放既有 take，输出 15 个 float32 视图、10 个原始声源、驾驶日志和 C 元数据。
- `checks.c`：原生状态／音频一致性、独立掩码空间渲染与分组闭合。
- `tools/render_source_audition.py`：冻结 take 校验、渲染、共同增益和原始文件索引。
- `tools/make_source_audition_page.py`、`source_audition_page.html`：简单播放器与显式机械独奏辅助文件。
- `tools/verify_source_audition_ui.cjs`、`verify_source_audition.py`：实际浏览器检查、独立样本校验、保全审计与版本冻结。

```powershell
cmake -S experiments/source_audition_v1 -B build-experiment-source-audition -G "Visual Studio 17 2022" -A x64
cmake --build build-experiment-source-audition --config Release --parallel
ctest --test-dir build-experiment-source-audition -C Release --output-on-failure
.\build-experiment-source-audition\Release\source_audition_probe.exe .\renders\v0.16.0\high_base.vsltake <新目录中的输出前缀> 2
```

Python 依赖沿用 `tools/runtime_review.py` 指定环境。完成后的固定目录有覆盖保护；重新研究应建立新版本。离线 observer 维护 7 套空间历史，本轮没有测试它在实时设备线程的性能，也没有将其接入原生 UI。稳定 `Launch.cmd` 和可选 `Launch-character.cmd` 保持原样。

## 验证与当前结论

1. CTest：独立掩码空间输出与原生置零对象结果一致；五种模板 × stereo／12 声道检查中，整个原生 engine、完整音频和原始声源逐字节不变。包括非默认空间参数和传播开启情形。
2. 8 个既有 stereo take 的完整 WAV 与驾驶日志均与 V016 冻结文件逐字节一致；其中 5 个 take 的 50 个原始声源也与先前独立导出逐字节一致。
3. 每组“单独＋去掉”与完整输出的最大 float 误差为 `1.4901161193847656e-08`；7 组求和最大误差为 `1.4915713109076023e-08`。全部视图均无输出削波。共同增益 PCM24 与辅助增益另有样本级量化误差校验。
4. 8000 RPM 各 65% 配方另导出 12 声道的 15 个视图；10 个源文件及完整驾驶日志与 stereo 相同。通道和坐标来自 C 元数据。这是路由／文件检查，没有实际 7.1.4 音箱阵列听评。
5. Chrome 实际静音解码／播放检查覆盖 120 个普通视图、8 个辅助机械独奏和 2 个参考。验证保留位置与播放状态、过期请求隔离、辅助增益复位、互斥播放、HTTP／file 入口及窄屏布局。HTTP 入口对本地 WAV 使用完整 Blob，解决现有本地服务器缺少 byte-range 导致定位归零的问题；不修改音频样本。
6. 原生 144 个源码／测试／构建约定文件、原生二进制、V011 四个主声线文件和经批准原始／float 素材保持哈希一致。此前 25 份快照的 manifest 身份记录在核查文件中；这不是再次检查所有旧快照内容。

此工具完成了可听的来源定位入口。现有机械对象较弱，已有细节层只有限改变高转规律性，这是后续实验的约束；没有证明“加随机性／机械电平就会真实”。下一轮需依据听辨结果定位主排气事件形状、传递响应或结构支路，再制作有边界的算法候选。总体目标中的实车音色标定与真实度验收仍未完成。

冻结索引：`baselines/source_audition_v1/manifest.json`。全部 float 视图、原始分轨与日志留在 `renders/source_audition_v1` 的哈希绑定路径；试听音频、界面、C 源码、生成调度、工具、二进制和证据另存快照。
