# 逐缸短压力源 · 实验 V1

[试听入口](逐缸压力源试听V1.html)。三个场景、三个按钮：现有 OSC／固定压力脉冲／逐次变化脉冲。优先比较 4000、8000 RPM，再听补油落转。页面匹配各版整段非加权 RMS，切换保留位置。此轮提供新的声源方向，尚没有主观验收。

用户最新优先级是“整体都偏电子，先加强逐次燃烧与机械细节”。当前主排气已有固定 Hz 共振包络、工况变化、缸列几何与逐次压力变化；问题不能归结为 OSC 数量不够。本轮先改变占主导的燃烧支路如何形成，不继续增加微弱附加模态。机械仍按原有独立模块工作，尚不能称这部分已经完成目标车标定。

## 本次改变

原主排气是连续低 DNA 与高阶 OSC；V019 另有已有事件驱动的分频增益候选。本实验读取同一批逐缸事件，为每次许可燃烧分别生成一个有起音、负压尾部和有限衰减的解析响应。响应不会随下一次燃烧重新调谐或截断。

脉冲为两个尺度的零积分波列之和，单个波列：

`g(t,tau) = exp(2)/16 × u³(4−u)exp(−u), u=t/tau, t>=0`

起点的值及前两阶导数连续；正峰在 `u=2`，尾部转负。两个 tau 的名义值为 75 / 28 微秒，权重 0.65 / 0.35；负载较低时乘 `1.25−0.25×pull`。这只是便于试听的**声学压力形状**，不是热力学缸压、真实燃烧持续时间或排气阀开启数据。当前直接以原有点火角作为声学触发约定，尚未识别真实排气开启与歧管传输迟滞。

固定版保留逐缸的既有静态权重，新增波列的持续时间及事件强度不随机改变。变化版再读现有 `character.energy[c] / shape[c]`，以 0.28 / 0.30 的有界工程深度改变事件强度与两个时间尺度。没有抽取新随机数；原有时钟和随机流逐位相同。固定版的其余原声支路仍有原有燃烧变化，不能把它理解为整个发动机完全无变化。

持续时间改变后，以解析积分得到的双尺度波列总能量进行校正，防止单纯变宽就自动变响；校正作用于**滤波前的连续形状**，不是最终混音能量保证。之后使用 4 倍采样、97 点 Blackman 窗 sinc 低通再抽取，截止为原采样率的 0.38 倍，群延时为 12 个原采样。右缸列另沿用原有 0.38 ms 的工程延时；录音左右声道没有被当成两个物理缸列。

令原主燃烧支路为 x，新事件源为 p，L 是 1000 Hz 二阶 Butterworth 低通。候选输出：

`y = x + 0.60 × [(p−L(p)) − (x−L(x))]`

原来的低通分量和 40% 的互补高通分量继续存在。交叉相位、短脉冲及其延迟都会改变完整波形；不能声称 1 kHz 以下音频逐样本不变。V011 四个声线文件、全部原生代码与原生二进制均未更改。

它是**无参考采样播放的程序合成替代方案**，运行时采用解析脉冲，并非严格纯正弦 OSC。单个形状可以作傅里叶展开，但不应借此把当前运行方式称为纯 OSC，也不能从本实验推出纯 OSC 无法真实。原 Pure OSC 模式保持精确旁路。是否值得将这种形成方式接入实时主程序，要由这组听评决定。

## 模块边界

| 文件 | 责任 |
|---|---|
| `experiments/firing_pulse_v1/profile.c/.h` | 独立工程配方：时间尺度、力度、交叉混合与逐次深度 |
| `kernel.c/.h` | 解析波列、连续能量积分、独立响应尾声、4 倍采样与抽取 |
| `adapter.c/.h` | 读取已有逐缸事件、共享燃烧许可、主排气交叉混合及右缸列延时 |
| `CMakeLists.txt` | 从冻结 V019 生成显式实例挂点的调度／take 副本，链接冻结 C 库 |
| `probe.c` | 严格 V019 take 重建、完整 float 混音、十个声源、状态与驾驶日志 |
| `checks.c` | 内核、能量、旁路、原状态、停机、分块及布局契约 |
| `tools/render_firing_pulse.py` | 固定输入、导出、试听切片与明确的 RMS 匹配 |
| `tools/verify_firing_pulse.py` | 独立解析／卷积、采样收敛、量化、原生与参考文件核查 |
| `tools/verify_firing_pulse_ui.cjs` | 本地播放器的静音浏览器操作与解码检查 |

插入点在原有排气求和后、原 IR 返回之前。只移除原主燃烧支路的部分高通分量并加入新响应；泵气、附加压力、机械、进气、气流和事件保持各自路径。body 有意接收改变后的排气 IR 返回。燃烧许可同时要求 RUNNING/CATCH、正燃烧许可与供给命令；拒绝新事件时响应可以继续衰减，不把旋转机械一并静音。模板切换、导入 DNA、Pure OSC、关闭原逐次燃烧时均旁路。

## 试听与验证

三个试听场景：4000 / 8000 工程 RPM 与 8 秒驻车补油。另有 5000 RPM 收油断油／恢复，作为状态验证。均为新录制、种子 48271 的严格 DSP019 take，四个既有实验力度均为 0；不翻译旧 take。

恒定转速试听裁取 2.5–5 秒，补油裁取 1.6–8 秒；原始全长 float 和十源均保留。PCM24 试听先施加 5 ms 余弦端点淡化，逐版使用已记录的恒定增益匹配 −23 dBFS 非加权 RMS，再共同约束峰值到 0.85。实际三版 RMS 差小于 0.0001 dB；没有 LUFS 匹配、压缩、限幅、降噪或新 EQ。原电平下，完整变化版的整段混音 RMS 比原声分别低约 0.535 / 1.062 / 0.274 dB，故不能直接拿原文件响度判断优劣。

批准 A 的手动参考沿用既有 `renders/event_color_v1/reference_A_exterior_blips.wav`，未重新清洗或下载。其 SHA256 与既有索引一致；固定 −6.02 dB 与 5 ms 端点处理保留。参考与合成未匹配 RPM、负载、麦克风或响度。

实际验证结果：

- CTest 通过：0 档与冻结 V019 精确相同；原驾驶、DNA、高阶、机械、逐缸事件与随机流保持；分块 1 / 257 帧结果相同；stereo / 12 声道十源相同；停机后不产生新响应；独立能量积分与数值积分一致。最初计数检查只覆盖约 1 秒，包含真实起动阶段，事件数不足；延长至约 2 秒后通过，算法未为此更改。
- 四场景所有原版 float WAV 与冻结 V019 逐字节相同。三版完整原声源状态哈希和驾驶 trace 一致；两个候选的接受事件计数一致，无拒绝事件误用、无响应槽溢出。除排气和有意接收其 IR 的 body 外，其余七源逐字节相同。
- 8000 RPM 的 stereo / 7.1.4 十源及状态、驾驶日志相同。没有进行物理 7.1.4 扬声器听评。
- 独立 Python 按解析波列、独立 FIR 和卷积计算 16 / 48 / 192 kHz C 输出，最大绝对差低于 `3e−8`（含 float32 量化）。本测试中 4 倍对 16 倍采样的差异相对信号分别约 −75 / −108 / −151 dB；仅是给定波列的数值收敛检查，不是所有变化参数的严格无混叠证明。
- 九个试听文件的实际样本、截取、淡化、恒定增益与 PCM24 量化独立核对。静音 Chrome 检查九文件加载、播放、位置保持、换场景归零、实录互斥、HTTP / 本地文件与窄屏；桌面、手机截图已检查。
- 当前原生 166 个源码／测试／构建入口文件与 app0191 快照一致；28 个冻结二进制文件哈希通过。原生设备代码未改，本轮不重复设备生命周期测试，也不把离线速度当作实时设备验收。

固定脉冲与变化脉冲用于分开判断“声源形成方式”和“逐次差异”。本轮没有据频谱或预测误差宣称真实度提高。若更接近所需方向，下一步是收敛这一个声源配方并接入实时控制；若只增加敲击或空腔感，应调整／放弃该候选，不能把这种特征当成真实机械细节。机械层标定、全工况音色、参考 RPM／负载识别和物理多声道验收仍在进行。
