# V0.10 连续启动与参考片段目录

本版为 0.10.0，构建 `build-v010`，入口 `Launch.cmd`。原 0.1～0.9 冻结历史保留，完整声线、空间和驾驶模拟目标继续为 active。

## 当前分层是否沿用仓库的方法论

采用 V6 的独立控制时钟、明确启动边沿、驾驶状态驱动声音模块的方法。DNA、BODY/PAD、NVH/空气与空间仍分开；内部实际有排气、机体、进气、机械、气流和高阶六类独立包络，底层再输出十个空间声源。它们随生命周期和运行状态分别响应。

| 状态 | 实际控制关系 |
|---|---|
| READY | 点火准备，不自动视为发动机运转 |
| CRANK | 曲轴转动、启动机和转动机械声；燃烧许可与燃料指令为零 |
| CATCH | 燃烧许可渐入，RPM 从实际拖动值连续带起、回落；六层各按自己的包络响应，音色增强随 flare 变化 |
| IDLE | 低转机体权重较高，排气与高阶保留怠速配置 |
| FREE REV / PULL / CRUISE | 分别映射进气、气流、高阶、机体保持等权重，不只调整主音量 |
| OVERRUN | 闭油门和负载改变谱形；满足驻留和迟滞后断油，泵气与转动机械声仍独立存在 |
| SHIFT CUT / REV MATCH / RECOVER | 离合、供给、内部补油与声层包络分开；内部补油不产生车轮推力，不冒充驾驶员松油 |
| STOPPING | 立即撤销燃烧许可；旋转、包络和机械模态各自衰减 |

运行状态配置在 `profiles/voicing.c`，当前仍是五模板共用的工程响应表；不是每款实车都已经测出了独立的 RPM×负载图。V6 的 V10 控制配置本身以 Ferrari 为上下文，不能直接当作 Lamborghini 数据。

## 修正了什么

旧版 `drive.c` 的 CATCH 入口直接计算 `idle + (1150-idle) × (1-ease(t/.65))`。入口 t=0 时，从约 215.67 RPM 直接变成 1150 RPM。音频端虽有平滑，控制层仍跳过燃烧带起过程。

本版将生命周期拆成 `src/drive/lifecycle.c/.h`，时间和转速常数放在 `src/profiles/lifecycle.c/.h`，`drive.c` 保留运行中的驾驶模型。CATCH 记录入口 RPM 与斜率，使用 Hermite 上升至峰值，再用 smoothstep 回落；峰值处斜率为零。六层音色增强改为消费同一阶段的 `lifecycle_flare`，不再在 CATCH 一开始就设置最大增强并立即指数下降。取消启动会立即清除燃烧许可和 flare。

保留工程设定：拖动 .28 s、220 RPM 目标与 .07 s 时间常数；带起 .20 s、回落 .45 s、1150 RPM 峰值；燃烧许可 .06 s 渐入；V10 怠速仍为 850 RPM。这是一条独立的启动控制包络，不是参考音频逐时刻拟合，也还不是扭矩／惯量求解。

V6 快照 `drive_model.js` 第 174～190 行使用明确 start 边沿，但也直接赋值为 `config.flare`；第 372～377 行从 flare 回落到 idle。此次借鉴其控制和发声分离的结构，修正本地的连续性，不把其启动曲线作为实车测量。上游快照不修改。

## 参考证据

新增 `references/segments_v1.json` 和 `tools/reference_segments.py`：统一七个有效区间、录音位置、允许用途、未确认项与原始／float32 主文件哈希。读取时保留双声道，不做隐式增益、清洗或混单声道。新的分析必须从目录取段。

旧 A 208–213 s 包含后面的车内切镜；新的车外低转分析使用 208–211 s。旧 313.5–319.5 s 开始于车内；新的车外行驶范围为 316–319.5 s。历史文件与 V09 结论范围保留，不回写伪装成旧版已用新片段。

启动段 A 33–40 s 为车内情境。重新从视频起点解码，抽取 29 帧，记录整数 PTS、时间基准、精确帧时间、命令及逐文件哈希。布局在 PTS 36.436436～36.636637 s 的采样之间变成圆形仪表。声音在约 36.65～37.2 s 宽带增强，随后约 37.2～38.1 s 低频谐波明显，再回落。这些只是图上人工观察的候选发声阶段，不是已确认的启动机断开／燃烧着车时间。

仪表开机、字幕消失均不能当作点火证据。音视频独立解码，尚未测得对齐偏差；360p 没有可靠读取转速。此次没有用这些时间替换运行时常数，也没有用车内谱形拟合车外排气 EQ。详细证据与边界见 `research/lifecycle_evidence_v010.json`、`references/analysis/lifecycle_v1/observations.json`。

## 验证与试听

12 项 CTest 通过。新增连续启动检查覆盖五模板及 1/5/10 ms 控制步长、CRANK 与 CATCH 中取消、重新启动、无车轮推力／误触发收油事件，以及选车时不制造启动边沿。原有运动挡保挡、安全降挡、供给、OSC、压力、机械与空间检查继续通过。

实际导出日志：CATCH 入口和前一行均为 215.672 RPM，入口跳变为零；采样峰值 1149.890 RPM；记录到的最大控制变化率约 6986 RPM/s。它说明连续性机制成立，不能换算成实车真实度。运动自动挡松油窗口保持 5 挡；关闭点火后燃料与燃烧许可持续为零。

有五组 V09/V010 同输入对照：启动、Pure OSC 启动、空挡补油、30 秒驾驶、手动换挡和停机。每组只使用一个共同固定增益，记录在 `renders/v0.10.0/verification.json`；没有对新旧分别归一化或压缩。改变启动会改变后续 OSC 相位，不声称新旧波形应逐字节相同。stereo／7.1.4 的十个源分轨继续逐字节相同。

实际 UI 静音检查通过启动、手动换挡、停止、导出、参数隔离和新旧预设；音频设备平均 1.2390 ms／512 帧，最大 3.5288 ms，设备 10.6347 s／墙钟 10.7537 s，队列耗空零次。浏览器完成十次版本／场景切换及两段参考载入、位置保持、播放互斥和手机宽度检查。自动播放保持静音，这些检查不是听音验收。

## 仍需完成

启动机本体仍是工程振荡器音色；冷／热启动差别、启动扭矩和惯量、失败启动、行驶中熄火后的离合与惯性、真实停机参考均未建立。现有 .55 s 停机与固定滑行衰减保持旧策略，不能作为物理驾驶模型使用。

本版没有解决高转主声线的真实度，也没有把 A 低转片段假设为 850 RPM。下一步需继续确认可辨识的谐波／阶次、负载谱形与进排气传递，再用留出片段检验；7.1.4 仍需实际阵列听音。
