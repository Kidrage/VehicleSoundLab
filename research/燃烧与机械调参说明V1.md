# 燃烧与机械 · 连续调参

上一轮已经冻结 `character_v1` 的四版对照。本轮保持音色配方与 V015 原生程序，补上独立调参面板：[打开连续调参](燃烧与机械调参V1.html)。它让用户在同一片段里逐渐调整压力和机械量，并把有用的设置准确保存，便于下一步决定哪些声音应迁入主程序。

## 使用

通过本机 `http://127.0.0.1:8789/research/燃烧与机械调参V1.html` 打开。选择 4000／8000 RPM 或补油、收油、30 秒驾驶，点击播放；两个强度滑杆分别控制逐次压力与机械结构。**切回基线**保留这两个参数与播放位置，再次点击即返回当前设置。监听音量同时作用于两种模式。

固定转速可循环 2.5～4.8 秒稳态片段，动态驾驶可循环整段。三条分量使用同一个采样起点和循环区间，L／R 保持独立。监听启停采用 5 ms 淡化，循环副本的两端采用共同的 5 ms 半余弦淡化，避免循环边界的突变干扰判断；原始数据不变。

**保存设置／载入设置**使用实验专用 JSON，记录片段、两个强度、监听音量、A/B 模式、循环状态、源哈希和目录哈希。只更新被触碰的控件；载入的非网格精确值保持原数值。文件属于此试听实验，不是 V015 原生预设，也不会静默改写主程序。

**导出整段 WAV**导出当前 A/B 模式与强度下的完整驾驶时长，48 kHz、float32、stereo。监听音量与片段共同固定增益写入输出；循环、启停淡化和当前播放位置不改变整段导出。文件的 RIFF `ICMT` 备注保存完整设置与来源，无需另找侧文件。导出是当前静态参数下的整段声音，不是录制滑杆移动过程。

## 声音与参数的对应

此面板播放的是已由 C 算法生成的固定驾驶结果，不在浏览器里模拟曲轴或车辆，也不把原车录音混入合成。主程序仍可实际驾驶、录制和回放；当前面板用于局部音色判断。

保持同一驾驶、种子、压力事件和空间历史时，两层增强与输出是线性关系：

`结果 = 基线 + 压力强度 × 压力增量 + 机械强度 × 机械增量`

增量来自相同片段的 C 混音之差，已经包含各自的声像与 IR 返回，不能把它们当成两个额外的麦克风或独立发动机缸列。强度范围为 0～1。准备脚本重新调用冻结 C 宿主核对六组 100%＋100% 边界，以及高转／驾驶两组 31.7%＋73.1% 非网格设置；与浏览器分量公式的最大原电平样本误差约 `2.24e−8`。

每个片段选定**一个固定增益**，覆盖整个参数方形的四个角，保证最高峰不超过 0.80，并将最响角的全片 RMS 约束在 −23 dBFS 以下。拖动强度不重新归一化，也没有压缩或降噪。该固定增益可能与上一轮四版页不同，比较时以各面板内部 A/B 为准。

浏览器监听和导出均保持双声道。Web Audio 强制使用 48 kHz，校验音频源 SHA256、声道数与长度后再启用控件。文件不完整或哈希不符时停止播放并禁用导出。这里增加的是 stereo 审听工具；原 C 的十源与 7.1.4 布局不变，未新增真实阵列验收。

## 模块与验证

| 文件 | 职责 |
|---|---|
| `research/character_tuner/app.js` | 控件、A/B、设置保存／加载与下载动作 |
| `audio.js` | 校验读取、48 kHz 同步播放、平滑增益、循环副本及独立离线 Web Audio 核验 |
| `mix.js` | 明确的混合公式与设置值校验 |
| `wave.js` | float32 RIFF／ICMT 导出 |
| `style.css` | 简洁桌面／窄屏布局 |
| `tools/prepare_character_tuner.py` | 十二条 float32 增量、共同增益与八次直接 C 对照 |
| `tools/verify_character_tuner.cjs` | 实际浏览器控件、静音监听、设置、下载及混音验证 |
| `tools/finalize_character_tuner.py` | 下载 WAV 的独立解析、源与历史完整性、当前进展及冻结 |

浏览器检查覆盖六组载入、三组各六种离线混音、同步起点、真实静音播放／暂停、A/B 保留位置、循环跨界与退出、淡化副本、参数隔离、非网格设置、无效 JSON 和损坏音频处理。离线 Web Audio 与明确公式的最大样本误差约 `4.7e−8`。还独立解码实际下载的候选／基线 WAV，核对音频、全片长度与文件内备注。

本轮没有改变声音配方；数值结果说明调参器忠实重现候选的混合关系。新候选的主观电子感、机械声是否过多、逐车标定、精确视频遥测与真实 7.1.4 听评仍未完成。听评记录保持用户原意，未新增接受结论。
