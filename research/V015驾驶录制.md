# V0.15 驾驶操作录制与回放

本轮补上实际操作的保存功能，声源、车辆状态机、工况分层和可选直达传播沿用 V014。它为以后比较同一段驾驶下的声音差异提供基线，本身不构成 V10 真实度的提升。

## 操作

双击工作区 `Launch.cmd`，点击 **New take**。新会话清空踏板、关闭点火；按 **Start**，再用 W／S、Q／E 或滑杆驾驶。Auto gears 沿用运动策略：松油保挡、制动时安全降挡。原有自动踏板编排也可以录制。

**Stop take** 或 **Stop monitor** 完成录制，自动存到 `E:\VehicleSoundLab\performances\take_日期_时间.vsltake`。**Save take** 可另存。**Play take** 读取文件，通过 C 状态机重新合成，仪表显示重建的运行状态；驾驶和音色控件锁定，Monitor 可中途停止。停止后恢复回放前的参数与外部素材选择，并回到点火关闭的新引擎。窗口关闭或更换录制前会保留未保存文件；保存失败会留在内存并在状态栏提示，不会直接丢弃录制后退出。

**Export 30 s** 仍从当前参数新建场景；实际驾驶记录请使用 take。离线导出实际 take：

```powershell
.\build-v015\Release\vsl_take_render.exe .\performances\某次驾驶.vsltake .\renders\驾驶.wav --trace .\renders\驾驶.csv
.\build-v015\Release\vsl_take_render.exe .\performances\某次驾驶.vsltake .\renders\驾驶714.wav --channels 12 --stems .\renders\驾驶源
```

CLI 输出原 DSP 电平的 48 kHz float32 WAV，无归一化、限幅追加或导出淡出。立体声导出验证录制指纹；12 通道输出使用相同输入和十条独立声源。源目录须先存在。端点完全沿用录制，分析前不要额外加工。软件诊断另提供固定 −6.0206 dB 的 PCM24 试听副本并记录处理。

## 状态与分层的关系

录制位于 UI／输入与状态机之间：输入 → 启停／车辆／换挡／供给状态 → 独立声音包络与瞬态 → DNA、机体、进气、机械、气流等声源 → 空间与监听。回放保存的是实际采用的输入，没有用一条录下的 RPM 曲线替换物理求解。工况仍区分怠速、空挡补油、带载加速、巡航、收油、换挡切断／恢复和降挡匹配；具体响应见 V03 与 README。

上游 V6 提供驾驶控制／状态／声层的组织起点。本地 take 是可重复实验的扩展，不是上游已有的录制模块。五模板仍共用工程车辆参数与部分响应表，尚未逐车实测标定。

## 模块与协议

| 模块 | 责任 |
|---|---|
| `session/parameters.c/.h` | 32 个参数的明确协议顺序、语义比较与有效范围，避免结构体填充字节 |
| `session/take.c/.h` | 预分配事件、有效 DNA／IR 快照、精确事件边界回放、float32 指纹 |
| `io/take_file.c/.h` | `VSLTAKE 1` 文本协议、双精度 17 位／float 9 位保存、严格验证与事务式加载／替换保存 |
| `io/take_render.c/.h` | 原电平 float32、驾驶日志和独立声源分轨 |
| `app/takes.c/.h` | 单独文件夹、自动保存与录制／回放生命周期 |
| `app/audio_device.c` | 音频线程实际采用输入时刻的记录、成功提交后计入音频与长度、设备回放 |

文件含版本、采样率、种子、长度、指纹、参数字段名、有效 DNA 系数、有效 IR 和输入事件。没有原参考录音、原始 C 内存镜像、系统绝对指针或外部素材依赖。IR 恢复后直接重建非零 tap，不二次归一化。

录制要求 frame=0 的新引擎，避免忽略录制前未知的曲轴、滤波器、随机流和传播历史。输入标记在实际采用它的音频块起点；原生 512 帧，即每块约 10.67 ms，不宣称 UI 输入零延迟或逐采样采集。回放按事件帧拆分任意主机缓冲，状态机仍按自身 200 Hz 控制时钟运行。录制线程不申请内存、不写磁盘。10 分钟和 65536 个变化事件有显式上限；设备提交失败丢弃未提交的末尾事件，保留可回放前缀。

解析拒绝截断、字段／版本不匹配、无穷／NaN、数值越界、重复或倒序事件、过大计数与尾随数据。先在临时对象完成验证，再替换已有 take。保存用目标目录临时文件完成后替换；失败保留原文件。

回放退出恢复音色、驾驶模式与外部素材选择，点火和踏板复位。跨版本对照需要今后显式迁移输入协议并建立新指纹，目前不会自动接受旧 DSP 录制。

## 验证与边界

详细数值见 `renders/v0.15.0/verification.json`、`workspace_audit.json`、`ui_take_smoke.json`。17 项 CTest 包括五模板的录制／读写／不同块长重建、导入 DNA 与有效 IR、立体声和 7.1.4 声源／完整驾驶状态一致，以及损坏文件和容量边界。

原生静音诊断会实际打开 waveOut、记录 Start→加速→手动换挡→音色控件变化→收油→停机→监听释放，并通过文件重新离线合成和设备回放。检查完整立体声 float32 FNV-1a64、最终完整驾驶状态、控件锁定、回放完结与中途停止、设备时长／墙钟和队列耗空。诊断录制的初始传播开启，控件探针的最终值可能在下一块取样前恢复；文件只记录音频线程真正采用的值。

既有 DNA 导入检查原来只渲染 2 秒、从 0.5 秒取样，在 V010 引入连续启动后会把尚未稳定的升转段当成稳态。此轮把诊断改为渲染 4 秒、只分析 2–3.95 秒，并排除导出淡出；V014 冻结核心与 V015 均检出 220 Hz，输出逐字节相同。没有放宽频率容差或修改变调算法。

指纹在设备静音、PCM16 量化和中途停止淡出之前计算。它确认同一软件构建的重建结果，不是声卡回录、加密签名、延迟测量或真实度评分。同版本不同编译器／数学库未必逐位一致；应保留相应冻结二进制。完整回放如指纹不一致会显示未验证；跨 DSP 版本直接拒绝。中途停止只验证正常退出，不要求不完整片段具有完整录制指纹。

V014 的监听实验与此前音色还需要主观反馈。车辆特定声纹、实际 ECU／DCT、生命周期物理耦合及真实 7.1.4 阵列听评仍未完成。
