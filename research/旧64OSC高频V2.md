# 旧 64 OSC：独立高频与实时 C 监听 V2

2026-11-10。用户明确选定 **旧 64 OSC** 为“最开始挺好，只差一点高频”的基准。身份与 SHA256 见 `timbre_baseline_20261110.json`；这不表示用户接受 V011、V020、上一轮新立体声拟合或任何新高频配方。

## 使用

双击工作区的 **`Launch-reference64.cmd`**，打开独立 C 监听窗口。默认音高 ×1.00、高频 0%；点“播放／重新开始”，可在六秒播放过程中调整：

- 音高 ×0.90–1.10：改变振荡器频率，保留声音过程的时间轴。
- 高频 0–50%：只增加从素材拟合的上层 OSC；0 回到原有底层。
- 停止：设备输出做短淡出并排空队列；再次播放从头重建。

这是独立的声纹参数预览，**还不是任意时长、任意 RPM／负载的驾驶音色**。原有完整驾驶 UI 及其所有版本保留。相对音高比例不冒充实测转速。

`research/旧64OSC高频V2.html` 保留原版／25%／50% 的固定对照，以及变调检查。建议从 2.6 秒后比较，因为高频提取仅覆盖确认的车外段。

## 底层与高频

底层使用早期检测器、相同区间匹配顺序和三次相位连接，重新导出系数及持续的分音 ID。在音高 1、高频 0 时，新 C 原始 float 输出与 V1 的 C 重建 **逐样本完全一致**；恢复旧试听的增益与端点淡化后，与已保存原版 PCM24 最大差异仍为一个量化单位。

高频不再使用上一轮“新立体声底层”。它直接加在用户确认的旧底层上，分为两个检测区间：3–8 kHz 最多 16 个支撑、8–14 kHz 最多 24 个支撑；短窗 2048、步长 256。来源是经目录读取并核对原始／float 主文件 hash 的 `A_exterior_moving`，316–319.5 秒。

历史六秒片段前部含车内视角切换。本轮没有从该部分提取新高频。为和旧底层比较，将目录主文件显式转换到历史的固定 0.5 增益、28 Hz 高通、单声道观察坐标；立体声主文件和旧片段本身保持不变。独立解码音频的波形相关检测发现 384 样本（8 ms）偏移，对齐后中央段相关约 `0.99999999`。这只是音频衍生文件对齐，不是视频、ECU 或点火计时。

只有检测窗及插值区间完整处于核准范围内的高频轨迹才被导出。高频有效区间是旧六秒时间轴的第 121600–286720 样本，约 2.533–5.973 秒；其余部分为零。统一使用旧版原有增益和 512 样本端点淡化，没有为候选分别配平音量、压缩或限幅。

| 同一车外重叠区间 | 3–8 kHz 功率差 | 8–14 kHz 功率差 |
|---|---:|---:|
| 旧 64 OSC | −1.99 dB | −17.48 dB |
| 加高频 25% | −1.91 dB | −13.32 dB |
| 加高频 50% | −1.72 dB | −8.75 dB |

差值相对于原录音同一片段；负值表示低于录音。高频缺口缩小，但尚未补齐，也不代表主观改善。残差混有源噪声、空间、编码与建模误差，不能称作已分离的发动机高频。

## 独立变调

每个检测到的分音在连续区间间保留身份，连接处校验幅度、频率和展开相位一致。音高改变时，在原三次相位上积累额外相位：

`Δφextra = (pitch − 1) × 原相位增量`

这样改变 OSC 频率的同时，不加速整条六秒控制轨迹。音高与高频目标使用 18 ms 平滑。处理函数没有文件读取、内存分配、随机噪声或事件触发；数据加载和状态内存分配在播放前完成。运行时不播放原始录音、残差 PCM 或波形表。

DSP 验证范围为相对音高 0.75–1.25，UI 保守限制为 0.90–1.10。加载前检查三次相位瞬时频率在最大比例下的余量；这不是任意 AM/FM 无混叠的数学证明。分音出生／消失使用原有幅度渐变；不同短轨迹间的相位关系在变调后仍需要听评。

## 对后续模型的启示

“64 OSC”是每个分析时刻最多 64 个检测支撑，声音过程会持续更换和连接分音，不是固定 64 根谐波。被认可的六秒模型共有 24228 个底层跟踪 ID，ID 寿命中位数约 16 ms。这也包含峰值选择和跟踪断裂，**不表示真实机械声源只持续 16 ms**。

因此，直接冻结一帧谐波表会丢失许多变化。后续可持续模型需要提取稳定的谱形／相对音高关系，同时保留短时幅度、频率、相位及分音替换的统计特征；不能把这些检测 ID 当作物理缸列或机械模态。先建立录音情境和相对音高条件，再接有证据的绝对 RPM／负载，沿用现有工况和分层结构。

当前 C 模块仍以已拟合的时间轨迹为输入；独立变调只是必要环节，没有完成持续状态建模、工况插值、实际动力学或声源／录音传递分离。高频与变调候选尚未获用户听感验收。

## 验证与维护

- 解析 AM／chirp 独立控制、立体声相位、1 与 257 帧分块一致性、原有 1 倍路径完全一致、平滑、无效目标和损坏分音 ID 文件检查通过。
- 实际 waveOut 静音播放六秒完整片段；原始合成 float hash 与离线输出相同：`056bc5460eb8ef69`。hash 位于试听增益／端点和静音设备转换之前，不是声卡模拟环回测量。
- 设备计时 6.000 秒，墙钟约 6.116 秒，队列耗尽 0；512 帧渲染平均约 1.54 ms、最大约 4.61 ms。另一次短播放通过真实 UI 消息改变两个滑杆，工作线程达到音高 1.1／高频 0.5。
- 浏览器六文件解码、车外段跳转、保留位置／播放状态、重复点击当前版本、本地文件／HTTP、窄屏检查通过。
- 隐藏窗口首次 `PrintWindow` 截图为黑图，第二次截取范围遗漏窗口边缘；两次证据留在 `native_attempt1/2`。最终通过本窗口 `WM_PRINT` 渲染完整窗口与控件，目视检查无裁切。这是截图路径修正，不是音色变化。

`experiments/reference_osc_v2/tracks.*` 管理轨迹身份与连接校验；`pitch.*` 管理连续相位合成；`audio.*` 管理设备线程和短停止淡出；`ui.c` 只处理窗口、控件与监听命令；`probe.c` 用于离线导出。沿用未修改的 V1 系数加载器；WAV I/O 从冻结源码编译，未引入 Max 或 JUCE 依赖。

`tools/reference_osc_v2` 包含导出、分音观测与绘图；`tools/review_reference_osc_v2.py` 生成新目录，拒绝覆盖。来源、系数、输出、代码与验证 hash 记录在 `references/analysis/reference_osc_v2`。当前原生驾驶源码不改，旧 64 OSC 原文件与所有冻结历史继续保留。
