# V0.2 状态分层核查

已经参考 VehicleSoundSynth V6 的生命周期、驾驶控制和分层方法，C 模块也已接通。当前仍是工程基线：不同工况有声音差异，但各层的工况声纹、瞬态和相互关系尚未完成 Lamborghini 标定。

本次检查只新增离线分析和说明，运行核心与冻结的 0.2.0 音色未改动。

## 代码中真正发生的事

控制链为：踏板／启动／挡位 → `src/drive/drive.c` → `src/core/orchestrator.c` → DNA、BODY、进气、机械、气流及事件 → 独立声源 → stereo／7.1.4。

生命周期与运行工况分开。工况标签用于显示和日志，持续声音主要依据转速、正负负载、油门、燃烧量和换挡量连续变化。**当前 `operating` 枚举本身没有直接查表选择另一套工况声纹。** 连续控制有利于平滑过渡，但不能把已有状态名理解成该状态已完成实车音色建模。

| 状态／过程 | 0.2.0 已实现的声音行为 | 待补齐 |
|---|---|---|
| OFF／READY | 不产生持续燃烧；单独点火不启动 | 尚无已核实的点火附件声素材 |
| CRANK | 独立的起动机合成包络，燃烧关闭 | 起动机脉冲、压缩阻力和实车时序标定 |
| CATCH | 燃烧快速接入；转速冲高后回到怠速 | 接火瞬间的排气、进气、机体各自谱形与包络；现在仍沿用运行层 |
| IDLE | 低转权重增加机体、机械和循环不均匀；DNA 低频包络变化 | 多个真实怠速状态及转速附近的细颗粒变化 |
| FREE REV | N 挡可补油而不推动车辆；转速、油门和负载改变声音 | 同转速下空载补油与带载加速的实测差异；不能只靠工况标签 |
| PULL | 正负载提高排气高共振比例、高阶分量、进气与气流激励 | RPM × 负载频谱表、瞬态与更可信的负载估计 |
| CRUISE | 延续当前转速、较小负载与各层连续权重 | 独立巡航标定；现在没有专门的巡航谱形 |
| OVERRUN | 负载可为负；DNA 有衰减与高频修饰；机体慢释放；快速松油可触发有限回火 | 燃油切断、残余排气、管腔／结构衰减、逐层关闭和恢复 |
| SHIFT CUT／RECOVER | 切断系数、转速衔接、恢复阶段；有条件的单次换挡事件 | 目前主要层共用燃烧 × 换挡系数；应进一步区分各层的切断深度和恢复过程 |
| STOPPING | 燃烧关闭、转速下降、包络和短 IR 收尾，取消待发回火 | 没有独立、已核实的真实熄火标定片段 |
| 滑行中的路噪／风噪 | 随车速变化，可在发动机关闭后继续 | 轮胎／路面与车身传递模型，当前只是工程化带限噪声 |

负责持续层的文件是 `dna.c`、`detail.c`、`pad.c`、`nvh.c`；调度在 `orchestrator.c`，起动机／回火／换挡瞬态在 `events.c`。事件需要历史门控，不是进入 OVERRUN 就不停爆音。

另一个明确差距：`engine.c` 已传递 acceleration，但目前 DNA／进气／排气没有消费这个变量。V6 的 V10 Gen 图会把正、负加速度分别用于进气和排气细节。因此“已计算加速度”和“已把加减速过程做到声音里”应分别验收。

## 与 V6 的具体关系

核对的公开修订为 `ac2b37d8639027d79934a2023cf8d1d37d3b2f96`。证据文件：

- `research/upstream_v6/code/drive_model.js`：固定控制时钟、启动锁存、踏板、车速、挡位、切断／衔接／恢复、条件收油。
- `research/upstream/gen/v10_powertrain.gendsp`：两缸列、怠速独立细节、intake／exhaust／residual、正负加速度着色。
- `research/upstream_v6/patchers/v10_pad_host~.maxpat`：独立 PAD 的连续转速／油门控制和电平。
- `research/upstream_v6/patchers/v10_cinematic_soundscape_host~.maxpat`：独立 soundscape 控制、由生命周期提供的运行状态。

V6 的 V10 图同样存在共享的 `engine_running * combustion_gain * shift_cut` 门控。这里提出逐层细化，是下一版需要验证的改进方向，并非声称 V6 已有完整的逐层物理瞬态。

V6 入口是四个独立 runtime；其 V10 标为 Ferrari reference。当前 C 的五个工程模板共享本地核心，既没有逐模块移植全部 V6，也没有把 Ferrari 数值冒充 Lamborghini 测量值。

## 实际测到的差异

可复现脚本：`tools/analyze_state_transitions.py`。数据、源文件哈希、CSV 和五幅频谱／包络图位于 `references/analysis/state_transitions_v1/`。

已有 C 导出在同样 5000 RPM 下，取文件 3–5.5 秒稳定区间，不做电平匹配：

| 有符号负载 | 输出 RMS dBFS | 3–8 kHz 能量占全频比例 |
|---|---:|---:|
| +0.12 轻载 | −38.22 | 0.231% |
| +0.85 重载 | −30.35 | 1.526% |
| −0.40 倒拖 | −41.56 | 0.132% |

这说明当前模型在相同转速下确实改变了幅度和频谱。它不证明变化符合真实车，更不是自然度评分。

A 原录音的两个短窗口 317.75–317.90 秒和 318.18–318.33 秒，按左右声道功率平均进行比较：

| 频带 | 后窗口相对前窗口 |
|---|---:|
| 28–120 Hz | +6.25 dB |
| 120–400 Hz | +5.72 dB |
| 400–1200 Hz | −8.23 dB |
| 1.2–3 kHz | −16.91 dB |
| 3–8 kHz | −19.56 dB |
| 8–16 kHz | −17.26 dB |

![A 行驶片段频谱和分频段包络](../references/analysis/state_transitions_v1/A_moving_exhaust.png)

这段录音的变化不是全频等比例降低：中高频明显回落，低中频仍保留，之后约 318.5–318.8 秒还有连续宽频瞬态。这提供了分层包络和事件调度的研究目标。**不能仅据此确定是收油、换挡还是回火，也不能把固定频带直接命名为机体／进气／排气。** 转速变化、声学传递、录音处理也能改变频段功率。

A 的 35.8–37.8 秒和 317.8／318.2／318.6 秒追加了视频画面抽查。可见仪表画面变化以及连续尾排外景；360p 画面仍不足以读出可靠绝对 RPM、踏板和精确接火时刻。B 本轮仍只有音频，没有视频状态确认。

![启动与尾排画面抽查](../references/analysis/state_transitions_v1/A_start_and_road_context.jpg)

分析窗口为 85.3 ms，步长 10 ms。自动峰值只是频段能量候选，JSON 中记录的半幅起落时间只是观测量，小于窗口长度的结果明确标为分辨率不足；不能直接写入控制器作为真实时间常数。没有把同片段分析当成留出集验证。

## 驾驶状态也需要审查

现有自动驾驶轨迹在约 14.94 秒从 5 升 6 挡，在约 15.61 秒从 6 升 7 挡，后一次已接近零油门。当前升挡阈值是 `maxrpm * (0.68 + 0.29 * throttle)`；松油会降低阈值，从而促成这两次升挡。

V6 的 `maybeShift` 也采用随油门降低的升挡阈值，直接参考它不能自动保证驾驶模式正确。这是驾驶策略选择，尚不能称为兰博基尼的错误行为。若目标是运动模式保挡，后续应增加明确的收油保持／制动降挡规则，并单独验证回火是否被换挡过程抑制。当前基线保持可复现。

## 下一版优先落点

1. **工况参数与包络**：在编排模块中表达排气、进气、机体、机械、气流各自的目标权重与起落时间；收油、换挡分别驱动这些过程。继续保留连续混合，避免硬切。
2. **声音过程**：独立描述接火、松油和换挡恢复的谱形与激励，不用提高随机噪声掩盖全部谐波／相位误差。
3. **标定与驾驶策略**：用可确认的动作和声音事件建立时间标签，保留未知 RPM／负载；划分参数拟合与检验片段。明确驾驶模式后验证保挡、升降挡及事件门控。

这些属于下一版本的工作，尚未写入冻结的 0.2.0。当前检查为后续算法修改提供依据，不代表整个目标已完成。
