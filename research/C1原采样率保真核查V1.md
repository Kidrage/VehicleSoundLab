# C1 原采样率保真核查 V1

目的：定位残留电子感相关的细节损失发生在哪一步。左右相位变化的听音反馈是“左右更自然，音色未退化”，但它没有解决声源的全部电子感。

本轮新增工具独立于正在运行的提取程序；不修改实时 C、已认可预设、房间处理、驾驶控制或录音素材。

## 对比链

```text
原始双声道录音，48 kHz
    ├─ 原声参考
    └─ 1025 tap / 22 kHz 声源 FIR
          └─ 同一条左右共享的 C1 时间坐标 → 相位域采样
                ├─ 原声源网格 → 原采样率重建
                └─ 全阶次 OSC 拟合网格 → 原采样率重建
```

分开观察三个差异：原声→声源 FIR 的频带损失、声源 FIR→网格往返重建的数值影响、声源网格→OSC 拟合的建模误差。两条重建支路都经过同一输出 FIR，避免把它的影响全算到拟合器上。

既往同段诊断已发现旧 14 kHz 声源 FIR 丢失高频；不能因此把所有电子感归因于这个滤波器。新的 22 kHz 提取仍需完成，才能判断实际保真度。

## 模块

| 文件 | 作用 |
|---|---|
| `tools/c1_native_diagnostics_v1/input.py` | 只接收独立数学核验通过的终态 C1 结果；绑定输入、报告和执行身份；逐点核对标量 OSC 与保存波形 |
| `tools/c1_native_diagnostics_v1/native.py` | 从真实上下文建立原声和声源 FIR 参考，恢复共同 C1 时间坐标，调用原采样率重建 |
| `tools/run_c1_native_diagnostics_v1.py` | 先处理四份已保存的人工已知案例；通过后才允许读取唯一真实提取终态 |
| `tools/audit_c1_native_diagnostics_v1.py` | 独立核对每个逆映射查询、插值、输出 FIR，以及全频谱和双声道统计 |
| `tools/c1_native_diagnostics_v1/declared_statistics.py` | 独立核对明确声明 FP64 均值舍入约定后的完整统计，保留旧比较失败 |
| `tools/audit_c1_native_declared_v1.py` | 人工控制先行，再审核保存结果；不重新拟合或修改观察数据 |
| `tools/run_c1_native_followthrough_v1.ps1` | 等待同一个真实提取进程；只在终态数学核验成功后执行单段原采样率诊断与独立审核 |

重建明确采用“保存网格＋sinc128 插值”，用于诊断，不等同于直接计算连续时间 OSC。新源输入使用的 C1 映射、22 kHz FIR 和长插值保持原身份，不冒用旧 PL/sinc128 源方法。

## 比较范围

- 原声、声源 FIR、源网格重建、拟合网格重建保持相同绝对时间和增益。
- 16×、32×只用于检查原采样率重建是否收敛，不代表实时 C 将采用这个倍率。
- 保留全部频谱、左右复数互谱、M/S、力度变动、跨频段协方差和时间滞后统计；高频弱能量区单列，不只看整段 RMS。
- 真实录音使用原准备目标的完整时间区间。人工已知案例目标不足一个 4096 点原采样率窗口，因此明确使用有真实上下文的较长区间。

## 与最终系统的关系

即使拟合录音和原声很接近，也仅说明能把声纹分析出来。下一步还必须让幅度、相位和时间变化成为可持续生成、可换随机种子、受转速／负载／状态控制的联合模型，才能沉淀成 DNA。

保存的录音波形和拟合系数时间线都不能充当循环发动机。左右录音关系也不代表已经分离出可直接部署到 7.1.4 的物理声源。房间和 IR 仍保持独立。

本轮不增加当前 C 算法负载。ADI 21569 的现有预算仍是 800 MCPS、预留 900 MCPS，尚无目标板实测。

## 本轮实际结果

四份保存的已知拟合均通过逐点 OSC、原采样率源网格／候选网格重建和 16／32 倍收敛核查；没有重新拟合这些案例。原采样率源网格相对解析声源的整段误差约为 `1e-7`。这是工具精度，不是真实发动机自然度。

旧独立统计审核在几乎稳定的正弦案例失败：其高精度求和均值与观察器的 FP64 顺序求和均值不同，减均值后的极小波动又放大了相对差异。完整检查保留了 20 个旧失败字段，最大相对差异约 `7.87e-8`，没有改变原 `2e-11` 门槛。

另立明确的 FP64 中心化审核，先通过变化／常数／零／单边静音／可观察舍入差异五类控制，再检查四份保存结果的每个重建查询、全频谱及全部统计。该审核通过，最大归一化比较差异为 `1.1704893185010757e-11`。它验证观察器实际声明的运算约定，不能把旧失败改称通过，也不是跨实现误差界。

`known1` 和 `known2` 保留了两个工具源码快照；第二次固定了新增独立审核模块。两者都只读取保存的人工已知拟合，不是重复提取真实素材。`known_audit1` 保留最初失败，`known_declared_audit1/2` 保存独立声明约定审核，`contract1` 保存一组成功和六类错误拒绝。

真实 FirstLate 提取及后续分析仍在进行。续接以 `c1_native_diagnostics_next_v1_plan.json` 和实际进程／终态收据为准。
