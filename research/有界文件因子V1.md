# 有界文件因子 V1

本轮把离线提取中最大的源矩阵和QR因子改为显式文件存储，原内存／原生后端保持默认。目的仍是完整保留真实录音的高频、逐次变化及左右关系，再学习持续可控声源；本轮没有新音色、试听或实时C替换。

前一阶段`efd9dea`已完成同一完整已知问题的基础三角／提前释放验证，真实六段连同上下文仍要求20.13–20.73GB可用空间，超过当时13.99GB物理可用量。因此本阶段先验证完整算法的有界存储，不减阶次、节点、因子、更新率或上下文。

## 模块

| 文件 | 职责 |
|---|---|
| `waveform_file_v1/store.py` | 独占创建FP64列主文件；明确区域读写、容量限制、短读写拒绝、逐文件I/O计数和哈希；不用映射 |
| `factor.py` | 自有Fortran面板GEQRF、后续面板ORMQR；完整R／反射器在文件，tau独立保存；按正确顺序应用Q／Qᵀ |
| `triangle.py` | 完整分块上三角／转置求解，遍历全部非对角块；没有块对角近似 |
| `graph.py`、`inverse.py` | 原图解、完整正交右基及恒等补空间；不做法方程分解、相消Woodbury或显式完整Q |
| `solver.py` | 按列生成原加权源，再按行块做原节点白化，避免内存中的完整X；原完整波形度量仍用带状根 |
| `pipeline.py` | 文件基础图解→释放带状根→文件右基／内层QR→固定两次原FFT修正 |
| 独立审计入口 | 原方程／高精度数值、完整左右轨迹、实际文件布局／原生缓冲区／I/O与退步记录分别核查 |

面板宽度只决定实现中的读写和原生调用尺寸，不改变问题。每个文件允许的单块FP64区域上限为`8 × max(行数,列数) × block`字节；原生QR／ORMQR／三角调用只接收自有连续Fortran面板，不把整个文件映射后传给LAPACK。完整输入／输出右端、带状度量和未登记的库内部临时空间另计，面板上限不是整个进程内存上限。

## 已完成的验证

- 12组矩形／方形QR控制覆盖1／3／4／16面板宽度，独立逐反射器核查完整Q、全部基方向、独立右端、零输入、R重建和正反三角求解。
- 原8组逆作用控制（宽／高／秩亏／零／极大／极小／混合尺度）及原7组任意Φ／W／R控制通过原Decimal80／110位和完整两次更新检查，恒等补空间保留。
- 12条输入／所有权／文件覆盖／区域／非有限值拒绝检查通过。
- 同一原12组与共享双声道8组均从原输入重新构建文件流程，独立通过原梯度2e-7、完整稳定停止量1e-11、后向一致性1e-11及两项gap门槛。延迟右声道独立停止量1.15645e-14，左右静音仍为精确零。
- 4组有限DFT、3组节点时间根及原生带状核直接沿用前一冻结版；独立审计确认相关当前源码哈希相同、原证据及上游清单一致，没有把重用写成新运行。

三次控制运行均保留：第一版验证基本文件算法，第二版增加三角原生调用和中间乘积登记，第三版改为每个写入面板登记一次并记录实际列拷贝，避免重复元数据淹没资源记录。数值控制全部通过，执行源码分别留在各证据目录；后续完整流程使用第三版。

分块改变浮点运算次序，不声称与旧版逐位相同。20组×7类输出数组的全部变化和80条有符号数值比较已保存，33条指标退步仍记录；最大q差约4.83e-13，最大波形模型残差差约7.06e-13，原完整normal历史最大差8.99e-8（延迟右声道，原尺度），各自原独立门槛均通过。它们不是主观听感改善证据。
