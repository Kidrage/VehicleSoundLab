# V020：实时燃烧事件声源

用户于2026-11-10明确允许“事件激励／共振，优先自然度，保留纯 OSC 对照”。V020把冻结的 firing_pulse_v1 解析压力源接入实时C11程序，保留V011连续排气配方。它是供试听的声源候选，尚未获得“更自然／接近实车”的主观认可。

## 操作

双击工作区的 **Launch-current.cmd**、**Launch-ui.cmd** 或 **Launch-v020.cmd**。启动时保持监听与点火关闭。使用工厂V10，打开 **Sound detail**：

1. 勾选 **Per-firing pressure variation**，关闭主界面的 **Pure OSC**。
2. 底部 **Pressure source** 选择 **Original OSC / Fixed combustion events / Variable combustion events**。
3. **Combustion source mix** 从100%开始比较；它对应候选原配方的60%互补高频替换，50%对应30%替换。其余四个旧实验滑杆先归零，方便单独比较声源。
4. 使用RPM/load bench比较1200、4000、8000 RPM；或使用踏板／自动驾驶。New take录制这些选择与驾驶操作，Play take精确重建。

Pure OSC是独立的严格振荡器对照开关，事件源会平滑退出。Original OSC则保留原有完整分层混音。事件源目前只适用于工厂V10；其他模板、导入DNA和关闭逐次压力变化时保持旁路。

[浏览器等RMS试听](V020燃烧声源试听.html)包含1200、4000、8000 RPM和空挡补油，每场景三版。它播放原生C程序的导出，不在浏览器内另做合成。整段非加权RMS匹配、记录恒定增益、共同峰值余量与5ms端点淡化；不是LUFS匹配。

## 模块和状态链

| 模块 | 职责 |
|---|---|
| `drive/` | 生命周期、实际驾驶与换挡、燃油许可；沿用原状态机 |
| `core/character.c` | 唯一逐缸事件与已有独立随机序列 |
| `core/pulse_kernel.c` | 解析双尺度零积分响应、独立尾音、4倍采样和FIR |
| `core/firing_source.c` | 读取事件、声源混合、实时模式过渡与右bank延时 |
| `profiles/firing_source.c` | 独立工程配方，便于维护和版本化 |
| `app/tuning.c` | 一个声源选择器与一个混合量 |
| `session/`、`io/` | 显式参数、严格版本的take和离线回放 |

同一状态机同时驱动DNA、PAD、机械、气流和事件层。新的压力源沿用 `vsl_fueling_allows_firing`：RUNNING/CATCH、燃烧许可和实际燃油命令同时允许才接受新激励。断油、停机和Strict OSC不产生新燃烧脉冲，已有响应继续衰减。它不根据音量包络猜测是否正在喷油。

声源模式0保留热运行的解析源／滤波历史，输出贡献为0；启用、停用和强度变化采用18ms逐样本平滑。固定／变化切换平滑改变后续点火的变化深度，不清空已有尾音。模板／导入／旁路转换对齐已读事件计数，不回放错过的点火，也不清空正在退出的响应。没有新RNG、第二个曲轴时钟、worker内存分配或文件I/O。

采用原候选公式：`y = x + 0.60 × mix × [(pulse − LP1000(pulse)) − (x − LP1000(x))]`。这里是互补滤波支路，不能理解成所有低于1kHz的波形都逐样本不变。核的75/28微秒尺度、负载伸缩、强度与持续时间变化均为声学工程设定；97tap FIR引入12个原生样本群延时，右bank另沿用0.38ms几何约定。这些不是实测缸压、喷油时刻、歧管传递或机械FRF。

声源仍在IR与空间化之前接入。原始进气／机械／气流等直接声源保持一致；排气通过已有IR回流到机体声层，因此湿BODY允许随排气改变。录音左右声道始终是话筒观测，不是这两个模型bank。

## 验证结果

- 23项CTest通过，包括实时混合、旁路、事件许可、无响应偷取、驾驶／原振荡器／RNG保持、立体声与7.1.4十路声源一致性，以及任意块长take重建。
- 真实waveOut静音监听：512帧、48kHz；平均约2.09ms、最大约5.17ms，预算10.67ms；队列断流观测为0，设备时长／墙钟约0.989。这是本机这次运行的结果，不是所有机器的性能保证。
- 实际控件隔离、浮点预设往返、缺省历史预设、录制、离线导出、设备回放、控件锁定和停止后恢复通过；新增源状态也与回放逐字节一致。下拉框标签经自身绘制与截图检查。第一次成功设备检查保存在 `renders/app0.20.0-attempt1`，调整隐藏诊断中的下拉标签绘制后重新核查，最终在 `renders/app0.20.0`。
- 四个既有场景的Original OSC完整float WAV与冻结DSP019逐字节一致。事件版从1.6秒后的最大绝对差不超过4.66e-10，确认实时接入保持上一轮离线候选配方；不代表该配方已主观达标。
- 新take：**DSP0.20.0 / schema5 / 38字段**。实测拒绝旧DSP019 take，不改写文件头。旧文件继续用 `Launch-app0191.cmd` 或对应历史入口重放。
- 浏览器12段文件解码、切换位置、播放／暂停、参考互斥、窄屏及HTTP／本地文件路径已核查。

证据：`renders/app0.20.0/native_verification.json`、`renders/v0.20.0/verification.json`、`renders/v0.20.0/browser_qa.json`。冻结目录 `baselines/v0.20.0` 保存本版代码、二进制与核查记录。

## 下一项判断

先比较固定事件与变化事件是否降低电子嗡鸣、是否增加不合适的硬敲击感，再决定声源配方。机械细节仍沿用已有模块，本轮没有同时改动它的音色，以便辨认主燃烧源的效果。D/E补充了台架和仪表情境，尚未提供可直接拟合的RPM×负载数据。目标车全工况标定、用户自制DNA转换和物理7.1.4听音仍未完成。
