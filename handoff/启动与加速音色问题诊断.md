# 启动与加速音色问题诊断

2026-11-17。用户否决V15启动声，认可怠速机械厚重感，但认为加速约20km/h后质感逐渐消失、声线单薄。此轮核查代码、参数身份与实际C分轨，没有改DSP、默认配方或用户窗口。

## 启动：旧候选的表达方式不足

刚启用的是 `voices/events_v1/profiles.json` 中A车内36.65–37.12秒／37.22–38.02秒的早期候选，**不是后续车外研究成果，也不是已认可的持续DNA核**。每段12个固定正弦加4条滤波噪声，无扫频、动态轮廓或实时RPM频率跟随；拖转主要门控，接火主要按指数衰减。它表达了有限谱色，尚未充分表达启动中的机械节奏、声线移动与燃烧建立。

事件策略读取RPM可用于其他策略，但这不等于把RPM送进启动振子。`event_control/scheduler.c` 的请求只带统一pitch/decay/texture；当前固定频率启动参数不会因生命周期RPM上升而跟随。

用原行程实际C重放4秒，PCM哈希与用户试听版本完全一致。接火观察窗0.65–1.25秒内，事件与DNA声线全窗同时发声；事件每声道RMS约−26.85dBFS，DNA声线约−34.70dBFS。旧候选明显参与并占主导。原素材是混合声，因此有把已含发动机主体的候选再次叠到DNA上的风险；并发本身不能量化物理重复成分，也不能单独证明哪项听觉瑕疵占比最大。

此前测试证明有声、触发正确、电平与回放可重复，**没有证明音色合格**。将这组候选直接启用并提高电平是不当的交付选择。用户否决现已记录。其他车外启动实验中的投影解释率，不能拿来当这组车内参数的实测结果，更不能当纯合成路线的极限。

## 加速：淡出执行正确，配方承接有失误

`modules/dna_character/voice.c` 使用：

```text
x = clamp((RPM / idleRPM - 1) / 3, 0, 1)
near = 1 - smoothstep(x)
指纹声线权重 = idle_blend × near
指纹纹理权重 = idle_blend × [near + (1-near) × air_continuity]
```

默认idle_blend=1、air_continuity=0.35，六组工况倍率均为1；默认辅助机械模板电平为0。用户听到的“机械感”不能直接等同于名为mechanical的辅助分轨。以下是850RPM怠速下的稳态目标系数，**不是感知比例或声学功率**：

| RPM | 指纹声线权重 | 指纹空气纹理权重 |
|---:|---:|---:|
| 850 | 100% | 100% |
| 2000 | 约57% | 约72% |
| 2500 | 约29% | 约54% |
| 3400 | 0% | 35% |

两者按约80ms时间常数平滑。因此“平滑消失”与实现一致；并无20km/h阈值，实际出现的车速取决于挡位、驾驶模式和RPM，用户本次会话未录制，不能反推精确转速。原意是避免怠速声线在高转过度变调，但替代主声线未充分承接机械厚重感。这个淡出是工程配方，**不是素材证明的真实发动机规律**。

## 收敛的修正方向

1. 固定用户认可的怠速作为基准，区分“随转速运动的谐波声线”与“持续保留的非谐波／有限相干机械纹理”；两条DNA角色在全工况存在，不随怠速权重一同退出。
2. 从现有加速素材测量纹理谱形、起伏、频带能量如何随局部转速趋势／负载变化，设计平滑连续响应。保留100%纹理只能作为定位手段，不能当作已完成的高转拟合；不把全部怠速特征直接拉高十倍。
3. 启动分成起动机拖转、燃烧建立、冲转回落。起动机单独生成；燃烧主体由同一DNA逐渐建立。先按原声核对动作边界、时长与可支持的转速趋势，无法确认的RPM明确标为估计。接火事件只补独立瞬态，避免用包含整段持续机声的模板再加一套主体。
4. 先完成与原声同条件的纯合成音色对照，再接回主App。执行正确、频谱接近或电平提高都不能代替听评；不新增平行前端、不盲目加噪声、EQ或振子数量。

代码仍能支持模块化修正，现有证据不足以判定OSC／程序合成路线不可行，也不能保证单靠增加正弦数量解决。此轮没有生成新合格音色。
