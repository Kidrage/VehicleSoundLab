# 性能优化与拖转升级计划 V1

2026-11-17。用户要求先整理方案并直接优化现有完整系统，在保护目前听感后升级拖转并听评；本阶段不以板载MCPS为约束，不做空间渲染。以下先作为执行计划，实测与结论另附结果。

执行已完成：公共内核五项改动、新会话v14及旧v13回放入口、96组持续OSC拖转候选。最终结果见[性能优化与持续拖转升级结果V1](性能优化与持续拖转升级结果V1.md)，试听为`startup_rotation_v1/listen2`。新拖转待人工听评，未替换App启动音。

## 执行顺序

1. 冻结原主声源v13、V3启动候选、参数与代码。建立完整声源的启动／怠速／加减速／参数变化／目录配方的输出、分轨与耗时基线。
2. 优化共同内核，逐项测量误差、状态过渡、分块一致性与实际性能；只采用通过验证且有收益的改动。新旧二进制分开，保留旧行程的原身份与播放器。
3. 将通过验证的库接入主App新启动会话，保留现有窗口。听感保护以保存PCM与各分轨误差、短窗／频带差异和控制回放为证据；数值一致不冒充新的人工听评。
4. 在优化后的基础上升级拖转：材料支持的相关OSC／转动调制、保留局部时间尺度，持续过程承担延长时长，分开移动声线与空气纹理。保持V3接火与怠速对照可追溯，给一份主要候选直接听评。

## 本轮优先优化

| 候选 | 做法 | 保护条件 |
|---|---|---|
| 实数FIR半谱 | 分区卷积仅保存并乘加非负频率，逆变换前恢复共轭频谱 | 滤波器长度、谱色、延迟不变；独立直接卷积、现有FIR检查及完整分轨误差通过 |
| 模态变调旋转递推 | 音高线性坡道期间递推每根OSC的旋转量，按小块及坡道边界重新校正 | 参数平滑、48k音频更新、相位连续与抗混叠权重保持；实测误差与长时间漂移受限 |
| 明确重复／固定计算 | 只缓存真正常量与已相同的计算，不改变随机流与音序 | 必须有重复成本证据；过去失败的幅度缓存不照搬 |
| 启动分阶段调度 | 新模型中按事件寿命运行；滤波尾部／预热有明确边界 | 不能直接停掉会在后续出声的随机或滤波状态；旧音色基线单独保留 |

不以删分音、统一削高频、降低声音采样率、冻结静音状态或简化协方差来冒充无损性能优化。近似数学运算必须单独报告最大误差、频带与时间误差，不能只凭听感猜测。

## 性能口径

比较同一PC、同一发布编译选项与缓冲大小；交替运行，报告处理时间、线程CPU时间、块耗时分位与最大值。文件读取、准备与哈希单列，不混入实时处理；初始化耗时同样保留。保存原新完整输出、分轨与采用的控制轨迹，覆盖交接和参数突变。

主系统与独立启动候选尚非同一个实时接线，分别测量，不能把离线试听的全程背景计算当成最终车载必需成本，也不能忽略未来实际需要的交接、预热与尾音。

本轮性能收益只代表当前PC和指定场景，不换算为21569 MCPS或最坏实时保证。最终优化与声音候选状态见后续结果记录。
