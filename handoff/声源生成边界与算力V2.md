# 声源生成边界与算力 V2

2026-11-16。用户明确：空间渲染由另一个仓库负责且有独立预算；本仓库只做纯合成声源生成、控制与分轨隔离，以供未来对象化。本文件更新[纯合成计划V1](车载纯合成实施计划V1.md)的责任边界及算力口径。纯声源入口、输入采用与独立操控窗口已初步实现；完整素材驱动的启动/回火事件系统仍在开发，未做算力优化或目标板计数。

2026-11-17复核：当前独立声源入口仍显式旁路空间处理，保留16类／23个原生干声通道及事件实例通知。下文395＋50＝445 MCPS仍为设计额度；V14历史估算没有覆盖新加入的四状态DNA参数执行，不能宣称是当前V9的实测或峰值上界。V9共用主相位，但各组锚点统计仍持续推进，状态混合也有成本，需要在后续独立周期模型／目标板计数中纳入。用户当前要求先明确生成边界，不在本轮开展DSP优化或渲染集成。

2026-11-17／V10再次确认：渲染仓库有额外预算，本仓库500 MCPS约束只覆盖声源生成、控制及干声分轨写入。实际调用为`vs_engine_process → ad_source_process_controlled → process(source_only=1)`，跳过scene更新／逐样本处理、空间投影与扬声器路由。旧适配器仍保留空间结构、链接依赖和少量控制字段平滑，尚未彻底拆除；这些实际执行的适配开销仍归生成侧。V10启动挡位修正不构成新的ADI周期估计，四状态统计及完整系统峰值仍未板测，445 MCPS不是已达成的最大值。

交给渲染侧的是原生mono／stereo干声及来源、样本时钟、事件类型／实例身份；不在此处指定扬声器位置。16类分轨中部分仍组合了算法子层，观察双声道也不是两个已分离物理声源，后续对象需求若需更细隔离，应在生成节点增加独立捕获，不能重复合成整条声源或把原录音L／R冒充独立尾排。

## 1. 现有代码确实含空间化

`src/spatial/scene.c`实现工程对象声像、可选几何传播、车内透视滤波、低频分配、早反射及最终高通，支持2/12通道。旧`ad_render_process`每样本调用`vsl_scene_tick`，包括直送监听模式；`spatial_mix=0`只选择干声输出，不停止渲染状态。故不能把关掉UI开关当作已删除渲染计算。新`ad_source_process`及受控版本显式跳过scene更新/推进和空间路由；工作台驾驶按钮已接入新[独立窗口](驾驶与声源控制台V1.md)，旧窗口另作历史对照。

独立`modules/sound_dna`核没有这些处理，但原录音提取的参数仍可能包含原始排气/机体/空间/麦克风贡献。输出不再加房间处理，不等于已从参数中物理去混响或分离声源。

## 2. 新的本仓库边界

```mermaid
flowchart LR
  I[车辆信号 / 键鼠 / 回放] --> C[唯一状态控制]
  C --> G[纯合成：DNA / 低频 / 细节 / 辅助 / 事件]
  G --> B[原生干声分轨 + 帧级时间 / 身份元数据]
  B --> R[另一个仓库：对象化 / 座舱传递 / 空间渲染]
```

本仓库计费：OSC、程序噪声、发动机/排气/机械共振、状态包络、事件调度、必要源滤波/抗混叠、干声增益和缓冲写入。声源塑形的滤波/共振不能当成空间渲染成本删除。

本仓库不计费、不在生产声源入口调用：听者位置声像、几何传播、座舱传递、房间/空间IR、HRTF/BRIR、扬声器路由、LFE分配、2→12通道渲染及渲染器输出设备处理。参数准备/状态重叠等发生在生成器内部的任务仍全部计入。

## 3. 调整后的代码计划

- 已新增`modules/vehicle_source/{api.h,assets.c,control.c,driver.c,source.c,stems.c}`：复用唯一驾驶器和原持续声源/事件生成，输出原生分轨；公开接口不暴露`VslSpatial`、扬声器数、监听位置或房间量。`atlas_adapter.h`是非实时旧配方迁移边界。
- 暂时保留原驾驶/空间监听适配器作历史对照和开发监听。新`vs_engine_process`经`ad_source_process`跳过`vsl_scene_update/tick`、`sb_route`和空间对象投影；不调用设备输出。严格身份/旧行程兼容另按原计划处理。
- 初步适配器仍借用`AdRender`/`VslEngine`，存储和链接依赖尚含未使用的空间部分；已验证处理时不推进空间状态，但尚未完成空间存储/依赖的彻底剥离，不能宣称已成为最小车载实现。
- 原`AdCapture`分轨和六层干声可作抽取起点，但必须进一步拆开辅助层和各事件，保留原生mono/stereo；不先投影成十个固定空间对象再输出。
- `event_synth`的四声部输出应保留类型、实例ID及音频帧；声部槽复用不能让外部把两次事件误认为同一对象生命周期。
- 原计划新增`src/spatial`功能、四轮空间对象实现和渲染性能测试从本仓库工作范围移出。只提供对象提示，位置/传递/扬声器映射由渲染侧决定。

首版声源类型至少保留：DNA、独立低频、非周期细节、进气、机械、排气空气、道路、风、启动拖转、接火补充、以及逐声部事件。怠速主声线/细节也可独立捕获。具体同时激活多少源遵守生成侧预算；不能因分轨数量增加而复制一套振荡器。

分轨元数据至少包含source ID、类型、mono/stereo、统一样本时间、有效帧数、事件实例/阶段、增益语义和对象提示；格式和传输协议待双方接口确定，不在此处假定另一个仓库的API。相干DNA/LF共用时钟，保留相位关系及生成器延时。此处“干声”表示未加本系统空间效果，不代表原素材已物理去混响。

已有录音DNA的观察L/R必须标成观察双声道，不能直接称左右缸列或两个独立尾排；程序独立生成的进气/事件等才按其明确来源给出对象提示。算法分轨隔离不能冒充从混合录音中分离出了真实物理声源。

## 4. 生成侧预算

维持单车、48kHz、240帧/5ms、四声部纯合成事件与原计划音色保护要求。将V1的60 MCPS“基础空间渲染与输出”删除，单列5 MCPS作为干声缓冲/轻量元数据输出额度；不重复计算已有主增益/混音。新分配如下，全部是设计额度，未板测。

| 生成侧部分 | MCPS额度 |
|---|---:|
| 主DNA、锚点统计与系数准备 | 215 |
| 独立相干低频 | 15 |
| 高频/非周期细节，含怠速共享纹理 | 45 |
| 怠速额外模态与交接适配 | 25 |
| 四声部事件，含启动/回火/换挡和尾音 | 30 |
| 连续进气/机械/道路/风辅助 | 15 |
| 输入/虚拟动力/状态/调度/常规混音 | 10 |
| 干声缓冲写入/轻量元数据输出 | 5 |
| 交接与系数准备突发 | 35 |
| 有效工作目标 | 395 |
| 执行争用/未知项预留 | 50 |
| 生成侧规划占用 | 445 |
| 相对500的未分配空间 | 55 |

395与445分别相当于每5ms块197.5万与222.5万核心周期，500上限为250万。相比V1的500规划占用，净释放55额度，不能声称已实测省55。后续可优先把未分配空间留给主DNA/怠速品质，不急着削减高频；如果重新分配需更新预算和峰值核查。

### 当前代码的生成量级能否直接从旧估计扣出

V14中的`auxiliary_events_basic_stereo_space`把辅助声源、事件和基础空间合在同一30–50 MCPS预留，不能把这个条目整体删除后宣称得到完整生成耗时。旧V1的275–531直接叠加范围也含渲染，因此不再作为生成侧范围。

现有估算能明确列出的认可行驶主生成项是DNA、纹理、LF、共振细节和控制，合计约208.37–392.66 MCPS；它未包含上述混合条目中的辅助/事件，更不代表新增全状态系统。在独立拆分/板测前，完整当前生成成本仍有未拆明项。

旧最重配方即便不计那项50和控制10，仅已列明的DNA/统计/512OSC残差等高端仍约734.06 MCPS。故另行给渲染预算并不会自动使所有旧目录配方满足500。395工作额度依然依赖V1的车载执行改造、轻量怠速候选和有界并发；主DNA215等分项不能当作已达成。

## 5. 验收变化

只对source-process包围的真实执行、必要准备任务和输出缓冲统计周期；不得把仍在同一DSP运行的源准备任务放到统计区外。覆盖启动→怠速→加速、锚点交界、换挡、回火/打滑重叠和统计/FFT同块。

声源层单独校验分轨和监听汇总一致、事件时间/身份、相干层同步、旧默认生成对照和长时间无空间状态推进。另一个渲染仓库的性能、声像和通道验收不纳入本仓库500计数；共享DSP/内存时实际争用仍需在约定运行环境中计入，而不重算对方算法周期。

## 6. 初步入口核查与剩余工作

`Build-Vehicle-Source.ps1`构建独立库、桥接DLL、分轨导出程序和边界核查。当前12种分轨共19个原生通道，提供DNA、低频、细节、进气、机械、排气空气、道路、风、启动纹理、接火、附加声源及旧事件/起动机。最后一轨仍是旧合并事件，尚不是新四声部事件池或逐实例输出。

12个目录预设各检查134400帧：与旧链干声逐样本一致、驾驶状态一致、空间内存不变、分块方式不改变声音；分轨重建误差小于2e-6。资产原始载入对象销毁后继续工作、非法参数/重叠缓冲/空间捕获拒绝也通过。首次测试因旧参考借用了已销毁预设的模型指针而崩溃，已改为借用独立持有的资产，原失败日志保留。

修改前/后目录导出进一步比较12份WAV及源哈希，保留原音色与旧播放链；代码身份随源文件修改变化，旧行程文件不宣称二进制相同。核查记录见[生成边界验证](../research/source_generation_boundary_v1_verification.json)。这不等于新音色获批或500 MCPS已达标。

外部速度/加速度/打滑采用、信号超时和独立上位窗口已实现，见[控制台说明](驾驶与声源控制台V1.md)及[验证记录](../research/vehicle_controller_v1_verification.json)。独立事件身份、新事件音色和彻底去除空间存储/链接依赖仍需继续；没有新增空间功能、修改认可声纹或做深层算法优化。

## 7. 独立事件后续实现

同日后续新增`event_control`及`event_synth`，已接入同一驾驶器/48kHz样本时钟；控制台V2支持事件宏参数、单次试听、四声部独奏及事件身份导出。分轨由原12类/19通道扩为16类/23通道；原有通道定义保留。详见[独立事件声源与提参V1](独立事件声源与提参V1.md)。目前只有A的启动早期纹理/接火两类未经听评的混合录音候选，回火等缺失类型保持禁用，不能称为全事件音色已完成。本节更新实现状态，不改变上述未实测设计预算；本轮优先系统和音色，没有做算力优化。
