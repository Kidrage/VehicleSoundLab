# 音频到参数：单状态任务文件

此入口把工作台流程变成可重复命令：**一份JSON＋一个已裁剪音频 → 分析／参数表／现有C试听**。无需启动网页服务；处理结果也会建成本地工程，可回到工作台调音。使用的是同一套分析器、统计编译器和C核，没有另一套命令行合成算法。

先复制 [任务模板](../examples/sound_designer/one_state.job.json)，把音频放在任务文件旁边，修改 `audio`、`name`、`state` 和 `viewpoint`。相对音频路径以任务文件目录为起点，支持中文和空格；也接受绝对路径。

## 两步使用

先分析：

```powershell
.\Design-Sound-Clip.ps1 -Job 'D:\MyVoice\idle.job.json' -Out 'D:\MyVoice\analysis1' -InspectOnly
```

查看输出的 `analysis.json`、`pitch_track.csv`、`bands.csv`，确认声学周期。把确认值填到任务的 `root_hz`，再生成参数：

```powershell
.\Design-Sound-Clip.ps1 -Job 'D:\MyVoice\idle.job.json' -Out 'D:\MyVoice\design1'
```

输出目录每次必须是新目录；已有结果不会覆盖。也可直接调用 `python tools/design_sound_clip.py <任务.json> --out <新目录> --workspace <数据目录>`。默认数据目录是 `E:\VehicleSoundLab`，依赖安装和C构建见[工作台说明](音色工作台使用说明.md)。

## 字段

| 字段 | 填写方法 |
|---|---|
| `schema` | 固定 `vsl.sound-design-job/1` |
| `name` | 必填，1–100字符的音色名称 |
| `audio` | 必填，本地已裁剪片段路径；不接受网址下载任务 |
| `state` | 必填：`idle`怠速、`steady`稳定转速、`acceleration`加速、`deceleration`收油、`blip`驻车补油、`startup`启动、`custom`自定义 |
| `viewpoint` | 必填：`exterior`车外／尾排、`cabin`车内、`engine`机舱、`unspecified`未知 |
| `selection` | 可选；`start`／`end`为秒，end为null表示到片段结束，选区至少0.4秒 |
| `root_hz` | 声学基频5–1000Hz；未确认为null。**不是RPM**，不自动推断气缸数／点火阶次 |
| `harmonics` | 默认 `auto`，按现有C带宽尽量选阶，最多320；也可给明确整数 |
| `components` | 0–16，默认12；实际保留数还受数据秩限制 |
| `allow_unstable` | 默认false；只有明确要固定音色草稿时设true，必须用JSON布尔值，不是字符串 |
| `parameters` | 与界面同名的宏参数，如 `gain_db`、`seconds`、`seed`、`low_db`、`high_db`、`detail`等，范围见工作台说明 |
| `source_sha256` | 第一次可为null；记录实际文件哈希后，可限制重跑必须使用同一音频 |

未知字段、重复JSON字段和越界参数会报错。标签只描述输入素材，不生成驾驶状态映射。

## 输出与返回状态

生成成功时，输出包含 `voice.model`、完整可编辑 `parameters.json`、`harmonics.csv`、`preview.wav`及当前版本ZIP。还保留原始任务 `job.input.json`、展开默认值／路径／文件哈希后的 `job.resolved.json`、分析表、音高轨迹／频带CSV，以及每阶段状态和输出哈希 `receipt.json`。`toolchain.json`记录Python／科学计算库版本及当次磁盘源码哈希；生成收据另记录C导出器哈希，方便追查跨版本差异。

| 返回码／status | 含义 |
|---|---|
| 0／`generated` | 参数与C试听已生成 |
| 0／`analyzed` | 显式只分析，未生成模型 |
| 3／`root_confirmation_required` | 分析已保存，基频仍需确认，不会静默选择首个候选 |
| 4／`stable_crop_required` | 周期不稳定或证据不足，需缩短选区；也可显式选择固定草稿 |
| 2／`failed` | 输入、文件哈希、带宽、构建或处理出错；查看错误和已保存收据 |

`receipt.json`记录工程编号和 `ui_path`。默认服务启动后，用 `http://127.0.0.1:8791` 加上该路径打开对应工程；也可在工作台“打开本地工程”里选它，或导入 `parameters.json`。

重复任务的模型和C输出可用于回归比较；ZIP时间戳、工程编号等记录不要求相同。高级逐分音／统计矩阵的人工编辑通过完整参数预设保存，这个任务格式用于从音频重新提取并应用宏参数。

## 已验证的范围

已验证中文路径、同任务重放、Python／PowerShell两入口一致、来源哈希与参数拒绝、标签贯穿分析／编译／导出，以及网页中未提取模型前修改状态／视角后仍能保留。

本机示例位于 `E:\VehicleSoundLab\renders\sound_design_jobs_v1\real1`：`A_fixed.job.json`使用已有归一化A固定参考，复现了之前工作台的300阶模型；`A_idle_inspect.job.json`对5秒原始怠速片段只做分析。后者存在周期候选歧义，未强行编译；观察到的短窗漂移不能当成真实转速变化。两者均无新的音色听评结论。

算法仍是固定平均声线＋幅度统计；频带上限外的细节不会自动补回。任意发动机高保真、加速轨迹、全工况和低频／噪声／事件层的自动参数化不在本入口已完成范围内。

实现入口：`tools/sound_designer/jobs.py`负责规范与流水线，`metadata.py`统一标签，`tools/design_sound_clip.py`负责CLI；底层继续复用 `workspace.py`、既有统计编译器和C导出器。验证收据见 `research/sound_design_jobs_v1_verification.json`。
