# App V19：程序回火与成本边界

2026-11-17。V18已有收油识别、连发策略、4声部事件合成池，但回火参数槽为空，因此驾驶页的许可开关不等于能发出回火。此前被否决的回火参考继续禁止复用。

V19补入一个**程序设计的回火候选**，让现有系统可以直接操作和听评。没有下载素材、播放录音或把被否决参考重新命名后使用；也没有实车回火拟合／听感验收的结论。

## 操作与调音

运行 `Launch-Vehicle-Sound.cmd`，默认V10已装载程序回火配方。

- 在“独立事件”页点击“收油回火 · 自定义”，可独立试听；引擎关闭也能手动试听。
- 正常驾驶或“完整流程”时，较高转速、持续给油后快速收油会自动触发。完整流程的收油发生在第19秒。
- “事件总电平”和回火右侧的分类型电平相乘；默认0.70×0.80。音高调低更沉，时长加大让尾声更长，程序纹理增加爆裂感。
- “触发配方”调整连发次数、间隔、重复强度、概率与冷却。默认1–2声、95–160ms间隔、重复强度0.72、概率1、冷却0.35秒；每个声音默认0.22秒。
- 驾驶页“允许收油回火”只禁止后续自动触发，当前尾音自然结束。手动试听绕过该自动许可与概率；关闭“启用独立事件”会释放声部并停止排队。
- “恢复默认事件”恢复程序候选。导入自定义音色可替换它；配方与控制行程保存完整参数、触发设置及身份，回放重新合成。

驾驶器现有门槛：平滑后的油门>0.35、RPM>1600持续至少0.12秒后武装；快速下降到<0.18、降幅>0.35、释放窗口<0.24秒、未换挡且冷却结束才产生机会。事件策略再决定延迟、概率与1–2声。上述都是工程策略，不是实车ECU标定。

## 声源及模块

| 文件／模块 | 职责 |
|---|---|
| `presets/events/procedural_afterfire_v1.json` | 可编辑的程序声音参数与明确的设计来源 |
| 同目录 `.h` | 同参数的C结构，使用现有导出器生成；可在C项目中调用`vs_engine_event_profile(engine, ES_AFTERFIRE, &vsl_procedural_afterfire_v1)` |
| `tools/vehicle_controller/afterfire.py` | 主App的默认装载、宏参数和连发配方；没有音频DSP |
| `event_control`（未改） | 收油机会、延迟、排队、声部请求及实例日志 |
| `event_synth`（未改） | 有限时长的4个阻尼OSC＋2个频带随机纹理，既有包络和小幅共同随机变化 |
| `vehicle_source`（未改） | 同一时钟上合成、输出原4个事件分轨及事件身份 |

声源设计为非等间距的短促低／中频共振和更快衰减的爆裂纹理，避免用持续锯齿波堆叠。没有额外FIR、房间模型、卷积、第二套DNA或新增事件声部。参数可调不等于音色已像目标车，后续仍应通过听评决定是否保留。

主App通过现有公开C参数接口装载，C运行核**没有改动或重编译**。仍为v16 DLL，SHA256 `7d22c302389c34168dfa19a78f810f597178c1891286d3e2b09111c1a9e3efea`。ABI12、preset9、take10、23输出通道不变。新参数在`presets/`而非历史`voices/`内，原录音声纹资产和编译事件库身份保持；新预设的完整事件覆盖表另外参与身份校验。

默认只给当前V10装载，不自动继承到其他车型、自定义DNA或旧DLL。读取／回放原配方采用它记录的覆盖表，旧V18行程不会被新默认注入回火。切换目录清除上一目录的事件覆盖，避免串音色。

## 算力边界

“不增加已有事件池容量”可以做到；“从空槽发声却严格不增加任何运算”不能靠复用接口保证。当前池原本允许4×12OSC＋4×4纹理频带，本候选满池只用4×4OSC＋4×2频带。容量上限和常驻模块不增加，未激活声部不跑振荡器或频带滤波；事件启用时的控制调度仍有极小工作量。

PC使用Windows `QueryThreadCycleTime`，每次3秒、5组交替顺序配对，测现有C桥处理及调用／拷贝边界：

| 场景 | 周期增量的配对中位 | 5组范围 |
|---|---:|---:|
| 已启用但不触发 | +0.32% | −0.25%～+1.53% |
| 强制4声部持续饱和 | +2.69% | +0.58%～+4.07% |

未触发差异处于这轮测试波动内，不能解释成负成本或证明零周期。默认每次1–2个0.22秒事件的平均占用小于饱和测试，但没有在此给出全驾驶周期平均百分比。结果不是ADI MCPS、板载峰值或硬实时保证。原事件预算已包含这些声部时可在预算内填充；若要求相对V18实际运行峰值一周期都不能增加，则需要进一步省出等量计算或在固定预算中替换，不能只填参数就作出保证。

首轮`thread_time_ns`呈15.625ms计量台阶，出现满载中位差0，因而没有用它宣称零开销；改用上述线程周期计数保留原测量以便审阅。
